## 2. 范围与非目标

### 2.1 PC-01 本次交付

1. 阅读器和版本列表的「下载说明书资料包」入口，绑定明确的 release ID。
2. 发起、等待、交给浏览器下载、失败与显式重试的状态；安全文件名与用途说明。
3. 现有登录态、错误恢复、键盘与 375px 窄屏可达性。
4. 使用真实后端生成并读取 ZIP 的独立验收，验证包身份、资产、清单与哈希。

### 2.2 PC-01 非目标

- 不新增导出格式，不实现 PDF 打印、ZIP 导入、整库备份、可双击运行的网站、公开分享链接或后台打包任务。
- 不修改发布不变量、不可变 manifest、资产归属、后端导出白名单，不把草稿或最新模型替换进历史版本。
- 不需要配置或调用 Tripo / 说明书 AI；不自动发布、生成、报价、上传外部资料。
- 不捆绑 B/C/D、模型栏防护、发行构建或真实供应商验收；这些分别保留在 §7。

本项目既有 E01 自动热点、E02 机械分件、E03 原生 PDF 准备、E04 多用户仍不计入本期，不因「符合 PRD」扩大。

## 5. 非功能与数据约束

- 下载用既有认证会话，GET 不增设修改权限或 CSRF 旁路；失败语义与现有 HTTP 客户端保持一致，不手抄 DTO。
- release ID、文件名、错误消息均不作为可执行 URL/HTML/路径。文件名只作浏览器下载建议，不影响包资产路径。
- 如使用 Object URL/临时前端资源，离开与完成后须释放，不长久保存在缓存/localStorage/sessionStorage；成功提示只能代表浏览器下载已被触发。
- 包生成仍沿用后端流式响应与临时文件清理，不为前端入口新增后端持久包缓存，不额外复制用户数据。
- 本批使用隔离临时数据与本机 fixture；不得借测试读取真实配置、输出密钥或触发真实收费请求。公开说明书仅落 Git 忽略的样本目录，记录来源和哈希，不自动纳入仓库 fixture。
- 当前可用空间约 4.1 GiB、Docker 不可用。本卡只做必要局部构建/测试，不启动大范围发行构建、不清理用户数据或已有缓存；测试遇到空间风险如实记录环境限制，不能削弱 AC。

### 6.2 下载状态与错误恢复

**UI-PC-003** 覆盖 AC-PC-003、004、005、006、007、009。两个入口复用相同状态约定：

| 状态 / 触发 | 按钮与就近反馈 | 恢复及焦点 |
| --- | --- | --- |
| 初始 | 「下载说明书资料包」；常驻用途说明可见 | 原生按钮，Tab 可到达，Enter / Space 启动；仅明确点击发起请求 |
| 请求进行中 | 同一按钮显示「正在打包…」，阻止再次提交；状态「正在准备此发布版本的资料包，可离开页面，返回后重新下载。」 | 不锁住页面导航，不显示虚构百分比、倒计时或后台任务链接；不抢焦点。可用 `aria-disabled` 保持焦点，但事件层必须同步防重；若用原生 disabled，必须确保没有焦点跳到其他操作 |
| 已取得有效成功响应并触发浏览器下载 | 按钮恢复「下载说明书资料包」；状态「已发起下载：{实际安全文件名}。请在浏览器下载列表中查看。」 | 不宣称「已保存到磁盘」「备份完成」；不把系统下载提示作为页面唯一反馈；再次点击是用户显式新下载 |
| 网络失败 | 「无法连接服务，资料包未下载。请检查连接后重试。」；按钮「重试下载」 | 无自动重试；恢复后仍下载原 release；重试清除旧错误并重新进入进行中 |
| 403 | 「没有下载该发布版本的权限。」；显示可用 requestId；提供「重试下载」，现有返回入口继续可用 | 不猜权限修改办法，不创建新版本；失败与该入口关联 |
| 404 | 「该发布版本已无法找到，请返回版本列表确认。」；显示可用 requestId；保留「重试下载」及既有返回入口 | 重试仍用原 ID，不偷偷切换最近版本 |
| 其他 HTTP / 服务失败 | 「资料包下载失败（HTTP {状态码}），请稍后重试。」；显示可用 requestId；按钮「重试下载」 | 不直接展示未知服务端 message、错误 HTML、内部路径或堆栈；保留原因类别与诊断 ID 足够支持定位 |
| 200 但不是有效 ZIP 下载响应 | 「服务返回的资料包格式不正确，未开始下载。请重试。」；有 requestId 则显示；按钮「重试下载」 | 不产生 JSON/HTML 文件，不以 `.zip` 扩展名就判定成功；内容校验方式由 RD 实现，QA 覆盖伪装成功响应 |
| 会话失效 401 | 使用现有统一登录失效流程，进入登录并保留原列表或阅读器路径 | 登录返回后为可显式下载状态，不自动重放请求、不在旧页面留下成功通知 |
| 下载中离开页面 / 切换到另一版本 | 正常站内离开，不弹离开确认；本页请求取消或结果丢弃，清理临时资源 | 不在新页触发旧下载或旧状态；返回后重新显式发起。下载已经交给浏览器后的磁盘操作由浏览器管理，页面不承诺可撤销 |

等待和成功使用就近 `role="status"` / polite 朗读；错误使用 `role="alert"`。各下载实例使用唯一说明/状态 ID，按钮以 `aria-describedby` 关联。错误出现不自动移焦，重试后焦点仍保留在该操作。短暂图标/旋转只能辅助文字，减少动效时不依赖动画传达状态。

**UI-PC-004 · 文件名及版本身份**，覆盖 AC-PC-001、005、008、010：优先使用响应 `Content-Disposition` 中合法的安全 ZIP 文件名；如文件名缺失、包含路径分隔符/控制字符或不符合安全 ZIP 建议名条件，则整体退回以当前 release ID 派生的确定安全名称（现有服务器默认 `release-{releaseId}.zip`），不展示原始不安全候选值。成功状态显示最终传给浏览器的同一个名字。不得用物品当前名称/草稿当前 revision 拼出仿佛新版本的文件名；不向用户展示 Object URL 或临时磁盘路径。

## 10. PC-06 模型栏误填密钥防护（PM_READY / 产品 revision 2）

### 10.1 问题、来源与识别规则

当前 `ProviderConfigStore::view` 把运行/已保存的 `model` 原样放入公共 DTO，前端再写入当前模型文本及编辑框；磁盘 `DiskProvider.model` 也是普通字段，只有真正的 `key.replace` 被加密。报价服务价格不匹配错误会嵌入模型原值。因此只修改输入框不能关闭本缺陷。

固定采用**高置信误填识别**，两家 provider 相同，前后端语义一致：

1. 对字段去除首尾空白后检查；可去除一个大小写不敏感的 `Bearer` 前缀及其后一个或多个 ASCII 空格。
2. 剩余完整字符串须以大小写敏感的 `sk-` 开头，后缀至少 **16 个**字符，且全部属于 ASCII 字母、数字、`_`、`-`，才分类为 `suspectedCredential`。整串匹配，不扫描普通文本中间的片段；已有控制字符/长度校验继续生效。
3. 不按长度、随机性、供应商白名单或是否出现在价格目录里猜测秘密。`org/custom-model`、`local:model-v2`、`sk-local` 等不匹配的合法自定义标识仍可保存；价格目录验证保持原阶段。
4. 这是有限模式防误填，不承诺识别任意供应商密钥，更不能仅凭用户输入以 `sk-` 开头宣称已经识别其完整格式。新增规则须有具体证据与同样的误伤测试。

状态用 `ProviderView.modelIssue = null | "suspectedCredential"` 区分正常/未填与问题值；该字段由 Rust DTO 生成到 OpenAPI/TS。问题值的公开 `model` 返回 null，**不得返回原值、部分前后缀、长度或哈希**。active 与 saved 各自分类，不用 pending 代替。

## 12. PC-03 跨会话恢复与下一步（PM_READY / 产品 revision 2）

### 12.1 PC-03A：从服务端发现并恢复 preparation

**REQ-PC3-001**：增加按document读取已有preparations的受保护能力，供准备页、确认页在无sessionStorage时使用。返回记录身份、document/source hash、状态、已完成页数/页号、已知总页数、更新时间、兼容性与推荐记录ID；列表有界可分页，推荐结果不能只从第一页猜。GET不创建记录、不补页、不收费。

**REQ-PC3-002**：兼容判据必须是document ID + 原件sha一致 + 受支持准备格式/页资产形态；仅浏览器缓存ID不充分。现行格式定义为v1（原PRD的页图/文字/viewport），旧记录只有能按现行存储事实确认符合v1才可标兼容，不按创建时间猜。缺页/资产缺失或不兼容保留明确说明，不能假显示0%或ready。无需把所有旧数据强行迁移；读取合同须区分兼容与不可复用。

默认推荐：兼容且完整ready优先；其次兼容preparing中已完成有效页最多；同等取updatedAt较新，再以ID稳定排序。用户可改选其他兼容记录。preparing未记录总页数时显示「已完成x页，总页数待读取原件」，不能把未知总数当0；用户点击继续后读取PDF真实总数并只处理缺页。ready直接供下一步报价，无重新PUT/封存。

**REQ-PC3-003**：sessionStorage仅加速候选查找，换标签页/浏览器或清除存储后仍可恢复。更换所选document立即重新发现记录，并验证缓存候选归属；原件不同不得引用旧ready。停止准备保留已完成页，文案明确“停止后可继续”；继续仍由用户发起，不在打开页面时渲染/上传整份PDF。并发准备沿用页幂等/If-Match，不静默覆盖冲突。

### 12.2 PC-03B：真实状态、推荐入口与建单恢复

**REQ-PC3-004**：服务端提供每物品摘要（列表批量返回或有界批量读取，不由前端每行发N套详情请求）。主动作优先级：需要处理的任务→运行中任务→待复核草稿→最新发布版→资料缺项/可报价。多个同类目标按最新updatedAt+ID稳定选择；明确目标entity ID，不返回可执行任意URL。保留已有发布版次入口，归档独立于处理状态。摘要失败保留概览入口，不猜状态。

**REQ-PC3-005**：向导完成状态来自当前资料：基本信息已保存；说明书绑定；front+至少一侧视图；兼容完整ready；当前报价有效且明确确认/已建任务。缺失为待补充，先前结果因当前输入改变失效为需重新检查；访问过页面不能算完成。新增推荐动作/状态不替代服务端最终校验。

**REQ-PC3-006**：确认页建单响应丢失/刷新后，先读取已保存报价的消费状态与consumedJobId，再恢复任务入口。一次操作的非秘密幂等标识可保留在受限浏览器状态作为提示，但服务端事实为准；未能核对结果时显示「结果待核对」并只提供读取恢复，不自动新建业务键/付费提交。没有已经发出请求的情况，用户重新明确提交仍可走现有同报价单任务合同；需要新报价时重新告知/确认。

### 14.5 PC-05B UI（UI_READY / ui_revision 2）

**UI-PC5-004 · 保存状态**：物品表单与每个知识修订区在操作旁显示「有未保存修改／正在保存…／已保存／保存失败，修改仍在本页」，与真正提交/成功响应一致。保存中同一操作不可重入；知识修订只有成功后才收起/更新成功状态，失败不卸载编辑框或丢输入。物品新建成功仍按已有路径进入说明书步，编辑成功按原路由返回概览；这些已确认保存的导航不触发离开警告。字段错误聚焦首个错误，网络错误保留重试；412 提示版本冲突，不自动替换编辑、更新 ETag 后偷偷覆盖。覆盖 AC-PC5-005。

**UI-PC5-005 · 离开保护**：站内链接、后退/前进或刷新/关闭在有未保存物品/知识编辑、上传或准备进行中时触发既有同类保护；同一离开只出现一个 dialog。普通阅读、无变化表单、已受理后台 job 不提示。站内对话框标题「离开当前页面？」按实际受影响内容说明：未保存编辑将丢弃；当前上传/本页准备将停止；已上传资料和成功准备页保留。只列当前真实后果，不列不存在的工作。按钮「继续处理」（默认焦点）和「离开页面」；Esc=继续、Tab约束单对话框，取消恢复原操作焦点/输入，接受才导航和停止本页未完成工作。原生 beforeunload 仅使用浏览器可支持的提示，不承诺定制其文案。覆盖 AC-PC5-004/005。

**UI-PC5-006 · 核对与丢弃**：412 后「核对最新版本」可读取服务端最新事实，但替换本地编辑前必须明确「丢弃本页修改并加载最新版本」的单次确认；取消保留原输入。401 提示登录失效并按原安全 next 返回，在同一页面会话内保留非密钥编辑于内存供登录返回后核对；不得为跨刷新保存而写 localStorage/sessionStorage。刷新/关闭接受后只能承诺服务端已保存资料可恢复，不能宣称未保存内容永久找回。401/网络失败不写“保存成功”，若响应结果不确定先读取核对，不重复盲发创建动作。覆盖 AC-PC5-005。

375px 保存/离开按钮44px且能换行；状态用 polite，失败用 alert，编辑正文/标签沿原14px基线；只读供应商事实快照和人工修订区仍分开。UI 不扩大为自动保存、离线同步或持久化知识正文。AC-PC5-004→005；005→004/005/006。生产实现可抽取已有 settings guard 复用，但 API设置已有保护须定向回归，不能多挂一个导致重复弹窗。
