# 社区与激励 PRD

状态：planned，产品与交互方案已输出，功能未实施。修订：1。更新日期：2026-10-04。反馈范围：第 6 项。建议优先级：P2，后续阶段。

## 1. 需求依据与目标

依据[用户请求与范围](request.md)及[原反馈第六节](../../../artifacts/ui-feedback-20261004/source/UI改稿反馈.md)：让用户上传、查看、评论和补充说明书，以成就、贡献者身份及权益支持共同维护资料库。

目标是形成“提交资料或补充 → 审核 → 其他成员使用 → 署名和贡献记录”的闭环。上传成功不代表内容已被采纳，阅读行为不等于知识已掌握；贡献度衡量被采纳的有效内容，阅读/使用以独立成就记录。

当前[架构](../../architecture.md)、[认证实现](../../../crates/server/src/http/auth/mod.rs)、[数据库](../../../migrations/0001_core_schema.sql)采用管理员身份，尚无本文的成员、贡献、评论与激励合同。社区会扩大信任边界，因此先完成 CI-00/01。方案默认服务于同一自托管实例的受邀成员，保留单二进制与 SQLite；公网匿名社区和多租户 SaaS 另列后续范围。

### 1.1 用户与衡量方式

| 用户 | 需要完成的事 | 观察结果 |
| --- | --- | --- |
| 阅读者 | 找到同型号资料，阅读原件/3D 内容，指出疑问 | 可以直接阅读被共享且已审核的资料，知道版本与来源 |
| 贡献者 | 上传缺失说明书、纠正或补充内容 | 能查看提交状态、退回原因、采纳署名和积分明细 |
| 审核者与管理员 | 控制资料质量，处理重复、举报与错误 | 有待审队列、证据、差异、操作审计和撤销入口 |

试点指标仅为测量口径，不虚构增长预测：每周新增有效资料数（去重后首次采纳）、补充采纳率（采纳件数/已结案件数）、7 日内有其他成员有效阅读的新增资料占比、审核时长中位数、采纳后 30 日内因无效内容撤销的比例。分母为零显示“暂无数据”。CI-06 用 fixture 核对口径；真实试点 4 周后再定增长目标。

## 2. 范围与分期

| 阶段 | 范围 | 发布条件 |
| --- | --- | --- |
| C0 基础 | 邀请成员、角色授权、私人/成员共享的可见性、身份迁移和审核规则 | CI-00/01 验收；旧资料仍私有 |
| C1 社区闭环 | 投稿与审核、共享资料库、评论/举报、补充建议/采纳、署名、站内通知 | CI-02～04 验收后可独立试用，不需要先上积分 |
| C2 激励闭环 | 贡献积分、阅读/使用成就、等级/身份、非付费权益、统计 | CI-05/06 验收；规则版本与撤销可追溯 |

本 PRD 的完整交付包含 C0～C2。阶段发布不等于第 6 项全部完成。非目标：开放注册、跨实例联邦、匿名公网索引、聊天私信、点赞榜、现金/礼品/付费生成额度、广告、电商、付费订阅，以及自动判定说明书或模型的事实正确性。

上传贡献可以只有 PDF，不强制四视图或 3D。3D 生成继续走原报价、预算与管理员授权；贡献和阅读不会自动购买供应商服务。所有积分数值与阈值是本次 v1 方案，可通过修订调整，不是原反馈已有数值。

### 3.1 角色和可见性

“成员共享”只对当前实例的正常登录成员可见；它不是互联网公开发布。界面使用明确文案“分享给本资料库成员”。

| 能力 | 普通成员 | 审核者 | 管理员 |
| --- | --- | --- | --- |
| 阅读已共享且有效的资料、下载其允许的文件 | 可以 | 可以 | 可以 |
| 私人草稿与未审核投稿 | 仅本人 | 分配的待审投稿及其提交快照 | 可按管理职责访问，写入审计 |
| 投稿、评论、补充、查看本人积分/通知 | 可以 | 可以 | 可以 |
| 采纳/退回投稿和补充、处理举报 | 不可以 | 可以，但不能审核自己的提交 | 可以，但不能审核自己的提交 |
| 邀请/停用账户、分配角色、社区开关和规则管理 | 不可以 | 不可以 | 可以 |
| API 配置、报价/付费生成、热点确认与正式版本发布 | 不可以 | 不可以 | 保持现有管理员流程和显式确认 |

高等级不改变角色。管理员自己的社区投稿也需另一个被授权审核者采纳；没有第二人时保留私人资料或待审，不以演示需求绕过规则。CI-01 的邀请可由管理员复制一次性链接分享，不要求新增邮件供应商；默认有效期 7 天、使用一次即失效、可撤销，令牌只存哈希且不写日志。成员使用独立登录凭据；管理员重置发一次性链接，重置后撤销旧会话，页面不展示原密码。

迁移后历史资产归原管理员，所有已存在发布版本仍保持原可见范围。社区投稿的待审文件通过受控审核快照读取，审核者不因此获得投稿者整个私人工作区权限。成员停用立即阻止新操作，既有有效共享贡献保留署名；永久删除账户时显示“已注销贡献者”，历史账本与审核记录保留必要的不可反向展示身份键。

### 3.2 投稿、补充与评论状态

| 对象 | 状态流转 | 约束 |
| --- | --- | --- |
| 投稿/补充 | 草稿 → 待审核 → 已采纳 / 待补充 / 已驳回 | 待补充可修改后重提；提交后冻结审核快照；驳回后可复制为新草稿并关联原记录 |
| 投稿/补充撤回 | 草稿/待审核/待补充 → 已撤回 | 投稿人显式撤回；待审核撤回与采纳竞争时，只允许一个成功结果 |
| 已采纳内容 | 已采纳 → 已撤销 | 作者可申请撤下，审核者按原因执行；公开展示关闭，必要奖励冲正；历史发布字节不改写 |
| 评论 | 待审核 → 可见 / 不通过；可见 → 已编辑待审核 / 已删除 / 已隐藏 | v1 全部评论和回复先审后展示；编辑期间先前已审版本继续可见并标“更新待审”，删除用占位保留回复关系 |
| 举报 | 待处理 → 已处理 / 不采纳 | 处理必须有结论/理由；不能靠举报数量自动删内容或给举报者积分 |

同文件 SHA256、同品牌/型号/语言/版本优先判定重复；若相同文件被填入不同型号，也提示审核核对。未获访问权的重复项仅显示“疑似重复，审核时核对”，不泄露私人条目的标题/作者/链接。重复采纳链接既有资料且不再次发上传积分；新语言、真实新版或替换破损文件由审核者说明差异，可作为有效新版本。补充按具体证据与解决的问题判断，不因拆成多条重复奖励。

采纳 PDF 投稿只形成社区资料，不等于创建 3D 模型或正式 release。补充采纳后显示独立、署名的“社区补充”，附证据和原始版本；如要进入正式说明书，由管理员把建议合并到新草稿，再走已有知识/模型复核与发布。社区内容与原文/已发布正文在视觉上明确分区。

### 3.3 积分、成就与权益规则

积分只衡量被审核采纳的内容贡献。积分账本是追加事件，不直接覆盖余额；每次发放/冲正包含成员、内容/事件 ID、规则版本、分值、时间和原因。同一事件的重复请求最多产生一次生效奖励。

| 行为 | 奖励规则 v1 | 去重与边界 |
| --- | --- | --- |
| 上传有效新说明书/独立新版并被采纳 | +20 贡献分；首次获得“资料贡献者”成就 | 每个去重后的资料版本只奖励一位有效投稿者；拒绝、重复、仅上传未采纳均为 0 |
| 有证据的修正/补充被采纳 | +5 贡献分；首次获得“共同修订”成就 | 每个独立问题的采纳事件一次；单成员每天最多 10 次计分，超出仍可采纳并署名，明确显示当日不计分且不自动补发 |
| 有效查看说明书 | 0 贡献分；首次“开始阅读”，阅读 5 份不同资料得“资料探索者” | 登录成员阅读自己以外的有效共享资料，前台累计 ≥30 秒且完成一次翻页/部件选择/步骤切换；同成员/资料版本仅累计一次 |
| 使用说明书完成一次操作记录 | 0 贡献分；首次“第一次实践”，在 3 份不同资料上完成得“动手实践者” | 仅对有步骤的共享版本，满足有效阅读后主动点“我已按说明完成本次操作”；每成员/资料版本一次；明确为用户自报，不表示验证实物或安全认证 |
| 评论、回复、登录、刷新、自我阅读、被浏览次数 | 0 贡献分 | 不以活动次数刷高贡献排名；v1 不做排行榜 |

阅读事件由服务端创建与当前会话/资料绑定的阅读会话，按服务端时间校验累计前台区间及操作事件；后台隐藏时停止累计、重复事件去重。客户端可以被伪造，因此阅读成就仅是低价值个人记录，绝不换算付费权益或角色权限。允许关闭本人阅读/使用成就记录：停止采集此类新事件，不影响阅读和投稿；不公开精确阅读时间线。

默认等级和权益如下；均为本 PRD 的建议值：

| 等级 | 条件 | 身份与权益 |
| --- | --- | --- |
| L0 成员 | 0～19 净贡献分 | 基础档案、阅读/投稿/评论能力；可创建 3 个私人收藏夹 |
| L1 贡献者 | 20～99 分，且 ≥1 条未撤销有效贡献 | 贡献者称号、资料署名中的等级标签；10 个私人收藏夹 |
| L2 共建者 | 100～299 分，且 ≥5 条未撤销有效贡献 | 共建者称号、档案印章样式；30 个私人收藏夹 |
| L3 资料达人 | ≥300 分，且 ≥15 条未撤销有效贡献 | 资料达人称号、可选档案边框；100 个私人收藏夹 |

等级取积分和条目数同时满足的最高级；边界值必须单测。收藏夹名称 1～40 字，成员只能看自己的；添加同一资料不重复，资料撤下后显示不可用并可移除。降级时不删除收藏夹或收藏记录，允许阅读、移除和重命名，超过新上限时暂禁新建；每夹条目上限默认 200，与等级无关。阅读、原件下载和已有 3D 体验不设置积分门槛。

内容因重复、无效或滥用被撤销时，按原规则冲正对应积分/成就资格，并重新计算等级。单纯作者退群/停用账户不抹掉有效贡献。误撤销恢复时通过关联原撤销记录的恢复事件返还一次奖励；不重复记作新贡献。阅读成就根据仍有效的不同资料计数重算，已被撤下资料不再计入；所有变化在本人明细中说明，净分最低为 0，不建立债务。规则升级仅作用于新事件；需重算历史时先形成规则迁移方案，不静默变更旧权益。

### 3.4 内容限制与处理

投稿要求说明资料来源并明确同意在本实例成员间共享；这只是产品分享确认，不推断上传者拥有任何权利。上传者不得将私人联系人/序列号等作为必需字段；提供问题举报与撤下途径，PDF 原文件不因投稿自动修改。

评论/回复为 1～2000 字纯文本，一级回复、禁止附件与可执行 HTML；外部地址仅作文本，不自动抓取或展开。补充建议为 1～4000 字且需证据定位。v1 默认每成员每日 10 次投稿/重提、20 次补充/重提、20 条评论/回复、10 次举报；待审投稿+补充同时最多 20 条。按实例配置时区结算每日限额，默认 Asia/Shanghai，并在页面说明。超限保留输入、给出可重试时间；幂等重放不重复消耗配额。

举报理由包括型号/事实错误、重复资料、分享问题、垃圾/骚扰及其他，说明上限 1000 字。举报只对举报者与审核方可见。首期不接外部自动内容审核；审核者人工处理，社区开关默认关闭。上述限额、长度与人工审核策略均为拟定产品规则，CI-00 可根据实际部署修订。

## 4. 验收条件

以下均为本项必选，当前未执行。验证使用至少两个普通成员、两个审核身份和管理员的独立会话及隔离 fixture。

| AC ID | Given / When | Then 与验证方式 |
| --- | --- | --- |
| AC-CI-001 | 旧单管理员库迁移；创建/撤销/重复使用/过期邀请，重置或停用成员 | 历史资料/发布字节和归属保留；账户不可共用管理员凭据；邀请只用一次；失效链接不可加入；停用/重置撤销旧会话。迁移、HTTP 与会话测试 |
| AC-CI-002 | 两成员交叉访问私人内容；普通成员/审核者直接调用管理、生成、发布和资产接口 | 私人内容不泄漏；401/403/不可见资源响应遵循冻结合同；Range/HEAD/缩略图/导出/备份同样校验；不能获取密钥/整库备份；积分不授予角色。接口负向测试 |

## 5. 非功能与数据约束

### 5.1 拟新增的数据合同

这些是领域要求，不是已存在的 API、表或迁移；CI-00 定稿后，按仓库规则以 Rust DTO/OpenAPI 为机器合同。

| 对象 | 必需信息与不变量 |
| --- | --- |
| 成员/角色/邀请 | 稳定成员 ID、昵称、凭据哈希、状态、角色、一次性邀请哈希/过期时间；登录会话绑定成员；原管理员身份可迁移 |
| 内容可见性 | 所有者、私人/成员共享、审核状态、共享快照、版本、撤下原因；原件及派生资产继承访问边界 |
| 投稿/补充 | 提交者、内容快照/文件 hash、关联型号/版本、来源/证据、状态、revision、采纳者与理由；同一有效采纳可追溯 |
| 评论/举报/审核日志 | 作者、所属资料版本、回复目标、文本版本、可见状态；审核操作/理由/时间只追加审计 |
| 激励账本/成就 | 成员、事件 ID、规则版本、分值、原奖励/冲正关联、幂等键、资格来源；余额为派生结果可重算 |
| 阅读/使用记录 | 有效阅读会话、去重后的成员/资料资格、本人自报使用、记录开关；详细前台活动片段默认 30 日清理，长期仅留成就必要去重事实 |
| 收藏/通知 | 所有者、列表与资料引用、事件目标、本人已读状态；私人隔离，不复制受限文件形成绕权入口 |

### 5.2 运行与一致性

SQLite 事务覆盖采纳决策、资料可见性与奖励事件记录；若派生通知/成就异步处理，持久化待处理事件，重启可继续且唯一键去重。新 API 继承 CSRF、Origin、大小校验与错误脱敏；所有写入受当前角色和对象权限限制。付费账本和社区积分账本严格分离。

迁移为追加式，实施前对旧库备份，验证保留发布快照、原管理员归属和旧会话处置。多用户使原本“登录即管理员”的信任假设失效，CI-00 必须盘点全路由和导出/备份入口，形成权限矩阵后才能开放成员登录。普通成员不得继承原管理员默认权限。

列表默认每页 20 条、最多 50 条，按稳定游标分页。页面失败保留已有列表和输入；新提交/审核操作显示处理中，未知结果先查询再用原幂等键重试。共享资料撤下后的未来请求必须拒绝；已经下载的文件无法远程收回，撤下文案需如实说明。普通成员不得读取完整备份，管理员按现有受控途径备份。

不记录 PDF 正文、评论内容或凭据到产品统计；详细数据仅用于内容与审核。头像首期使用本地生成的文字头像，不引入上传头像处理链。准确的日配额/规则版本/生效日显示在提交与权益说明中，不用隐藏规则扣分。

## 6. UI 交互设计

### 6.1 页面与导航

下列为拟新增入口，CI-00 定稿路径；现有阅读器路径保持可用。共享库称“共建资料库”，与管理员私人“我的资料”分开，入口仅在社区开启且有相应权限时出现。视觉沿用[视觉 PRD](visual-style-prd.md)的网格、编号和克制印章风格。

| 页面建议 | 信息结构与主操作 |
| --- | --- |
| `/community` 共建资料库 | 品牌/型号搜索 → 资料类型/语言筛选 → 已审资料列表；主操作“贡献说明书”；无内容时解释如何贡献，不填充假数据 |
| `/community/manuals/:id` 资料详情 | 名称/型号/语言/版本 → 阅读/原件 → 来源与贡献者 → 社区补充 → 评论；使用成就置于步骤完成后的次要位置，不遮挡正文 |
| `/contributions/new`、`/contributions/:id` | 选原文件和填写来源 → 检查型号/疑似重复 → 预览分享范围 → 显式提交；详情展示审核时间线、退回理由和继续编辑 |
| `/me/contributions`、`/contributors/:id` | 本人列表可见所有状态；他人档案仅有效贡献、净积分、称号和可公开成就；私人成就默认仅本人可见 |
| `/me/achievements`、`/me/collections` | 成就条件/当前进度、积分收支、等级与权益；收藏夹新建/重命名/移除；等级条件可展开，不用连续签到压力文案 |
| `/moderation` | 审核待办按投稿/补充/评论/举报分组；原件、来源、差异与处理理由同屏；先审内容再处理结果，禁止只看积分批准 |
| `/notifications`、成员管理 | 站内结果通知；管理员邀请/停用/角色与开关；说明分享范围和默认规则 |

### 6.2 核心路径

```text
成员：共建资料库 → 搜索型号 → 阅读原件/3D → 评论 或 提交带证据的补充
贡献者：贡献说明书 → 填来源和分享确认 → 待审 → 采纳/需补充/驳回 → 本人贡献记录
审核者：待审队列 → 核对原件/重复/证据 → 处理并说明理由 → 共享资料/社区补充
激励：采纳事件 → 一次性记账 → 重算等级/权益 → 站内通知与可查明细
```
