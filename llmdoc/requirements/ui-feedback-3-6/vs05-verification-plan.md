## 发行门禁

1. 记录最终源码文件 SHA 清单、Git 基准及工作树变更；产物必须绑定该来源，不把脏工作树包装为已提交版本。
2. 执行 `cargo xtask check` 和当前版前端/E2E；单独记录各套件测试数、环境、失败和忽略条件。
3. 构建 macOS Apple Silicon 内嵌前端正式包，执行可复现性检查和七步冷目录 smoke。使用隔离样本备份，禁止连接当前用户资料库。
4. 从同一源码构建 Linux AMD64 镜像/静态程序，执行工程检查、独立 Compose 六阶段验证及无网络、无源码/Node/Python 的正式包读取/重启/恢复。
5. 打包可执行程序、校验和、构建/依赖/许可证清单、Docker 部署所需文件以及启动/升级/回滚说明。部署入口须明确指向新产物，不能复用旧预览程序。
6. 生产公网配置须保留明确 HTTPS origin 与受信代理边界，不能以本机 loopback HTTP 冒充已验证实际生产域名。当前交付范围是可部署产物；无生产域名/服务器时不声称已经公网部署。

## 隔离与证据约束

使用新的 `var/ui-feedback-3-6-vs05-*` 与临时目录；测试端口避开 8080/5173 及 Claude 的当前端口。普通 E2E 中硬编码历史证据的套件须先保留快照或在隔离源目录运行。密钥测试使用专用 fixture，按现有规定禁用 trace/自动截图。

Docker 验证使用 `scripts/verify-docker.sh` 的独立项目/卷和固定 image ID；不能调用固定项目名的日常 `start-project.sh --docker` 替换用户服务。正式包原生启动采用独立 root、端口、`EM_PREVIEW_BINARY` 与 `--embedded-ui`。仅结束本轮创建的进程与容器。

本轮不默认购买供应商任务。历史真实 Nikon 生成证据可说明既有能力，本次展示变更的发布报告另列实际验证范围。原生 Linux ARM64、物理 x86、Windows 与 Intel macOS 未实测时准确标明。
