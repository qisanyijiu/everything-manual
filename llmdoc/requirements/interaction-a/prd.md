# interaction-a PRD：流程与可达性

状态：本批已完成，独立 QA 第 2 轮 PASS · 修订：1 · 更新日期：2026-09-20。12/12 AC 通过，IA-BUG-001 已关闭；详见 [实施交接](implementation.md) 与 [QA 报告](qa-report.md)。本结论只覆盖切片 A。

## 1. 需求依据与目标

用户要求「按照这个改进方案开始改」。本批依据 [request](request.md) 与 [交互体验改进方案 §6 切片 A](../../../docs/interaction-experience-improvement-plan.md#6-实施顺序与交付切片)，交付创建跳转、确认页重排、标签键盘操作和关键文字/触控尺寸。成功指用户创建后直接进入上传，任何约定屏宽都能沿主页面读到预算与发送确认，纯键盘可以切换多面板标签。

这是原方案的首个实施切片，不代表 UX-01–UX-10 全部完成。原 [web-mvp PRD](../web-mvp/prd.md) 的业务不变量继续适用；本目录不修改 T22/T23 的发布和真实供应商验收状态。

实现依据（2026-09-19 静态核对）：[ItemFormPage](../../../apps/web/src/features/library/ItemFormPage.tsx) 创建后进入概览；[ConfirmStepPage](../../../apps/web/src/features/import/ConfirmStepPage.tsx) 报价与确认分处 rail/aside，确认勾选与服务端确认状态分开；[PageLayout](../../../apps/web/src/features/shell/PageLayout.tsx) 中屏标签已有 roving tabIndex，但没有方向键处理；[theme.css](../../../apps/web/src/theme.css) 存在小字号和较小按钮。以上是源码事实，不作为本批已验证的运行结果。

## 2. 范围与非目标

本批覆盖 UX-02 的创建成功跳转、UX-04 的确认主流程、UX-08 的标签键盘行为与关键字号/点击区。沿用现有暖白、墨绿、橙色主题、路由、请求和数据，不新增 API、后端字段、存储或依赖。

明确延后：向导真实完成/失效状态；拖放上传、文件卡片、局部重试和方向示意；跨标签页准备恢复；资料库下一步摘要；复核待办定位；隐藏原文的自动唤起；跨刷新建单结果恢复；搜索、导出、统一离开保护。本批不因缺少完成状态而用「访问过页面」推断资料完成。

确认页仍可保留现有任务受理区域和「查看任务详情」入口；本批不要求自动跳转任务页，也不新增视图缩略图资源请求。UX-04 的主流程连续性以预算、发送范围、勾选与生成全部可直接阅读为验收边界。

- 沿用 React/TypeScript、现有 CSS 和 API；不改变 Rust DTO/OpenAPI、费用整数单位、确认接口、已发布内容和单二进制运行边界。依据 [architecture](../../architecture.md)、[contracts §4](../../contracts.md#4-输入快照与费用合同)、ADR-003/006/009。

- 375/768/1024/1440px 为本批布局检查点；44px 与字号阈值为本项目设计验收指标，不宣称已经符合外部无障碍认证。

## 6. UI 交互设计

UI 状态：**UI_READY**（设计冻结记录）；对应 PRD 修订：1；ui_revision：1；冻结日期：2026-09-19。以下为本批设计要求，任务 `IA-01` 使用本节与 §3–5 一起验收；2026-09-20 的实现与独立验收结果见文首链接。

### 6.1 页面与导航

**UI-001 · 创建与上传连续（REQ-001；AC-001、AC-002）**

- `/items/new` 维持名称、型号必填，品牌、配置可选；保留现有字段校验、错误摘要与首个错误字段焦点。主按钮为「创建并继续」，提交中禁用并显示进行中状态。
- 创建成功后只进行一次路由跳转：`/items/{响应 id}/import/document`。保留「已创建物品…」成功通知，目标页显示现有说明书上传内容和第 2 步的当前位置。不得在导航时额外上传或再次创建物品。
- 创建失败停留表单并保留输入。`/items/:itemId/edit` 的「保存」仍返回物品概览，412/428 的内容保留与刷新入口保持现有行为。
- 步骤条继续表示当前位置，本片不新增「已完成」标记；PDF 上传、资料准备、离开提示沿用现状，跨标签页恢复与新的站内离开保护不在本片内。

**UI-002 · 确认页的单一阅读路径（REQ-002、REQ-003；AC-003–AC-005）**

路由继续为 `/items/:itemId/import/confirm`。移除该页对报价 rail 和发送范围 aside 的依赖；只保留一份内容及一套表单控件，全部随主页面正常滚动。桌面可以在一个区域内并排展示两类金额或预算字段，但 DOM 顺序与下列视觉阅读顺序一致；不将确认框或主操作放回独立侧栏。

```text
向导步骤 → 预算与隐私确认 → 当前物品与简短说明
资料情况 / 缺项 / 读取或报价错误 + 原有修复入口

报价与预算
  Tripo credits：预计 / 保守上界 / 授权上限输入
  说明书 AI USD：预计 / 保守上界 / 授权上限输入
  价格版本、快照、页范围、有效期、预算语义

将发送的资料
  Tripo：视图照片、模型与预设
  说明书 AI：物品型号、页范围、文字页 / 页图页、模型
  可展开的参数与校验信息（如采用折叠）

云端发送确认
  [ ] 我已阅读并确认将上述资料发送给对应供应商
  当前保存状态 / 确认错误

生成操作 + 紧邻的禁用原因 / 手动重新报价入口
或：任务已受理 + 后台执行说明 + 查看任务详情
```

- 375/768/1024/1440px 均保持上述纵向主流程；手机金额区域和预算输入改为单列。主内容建议不超过约 960px，卡片/区域允许自然增高，不设压缩文字的固定高度。卡片内边距可沿用桌面 24px、手机 20px，延续暖白底、墨绿标题、橙色主操作。
- 金额区保留服务端的全部费用显示与单位。有效期与预算语义不折叠；价格版本/快照信息至少 12px。技术参数、哈希允许放在有明确标题的原生 `details` 内，接收方、照片方向、页范围/页类型、型号、模型及预算信息不能只藏于折叠区。无需新增缩略图请求。
- 预算格式错误与低于上界提示贴近对应输入，沿用 `aria-invalid`、关联说明。生成禁用原因紧邻主按钮，并以 `aria-describedby` 关联；不能只靠按钮变灰解释原因。发送确认的产品说明使用「确认后才能开始生成」等可理解文案，审计事件内部名称不作为用户完成操作的必要信息。
- 加载时显示带文字的占位内容；缺资料展示现有缺项及修复链接；报价失败保留「重试获取报价」与服务状态入口。没有报价时只展示缺失状态，禁止用 0 元占位。过期明确显示「报价已过期，重新获取后再确认」，仅显式点击重新报价；输入变化响应保留返回资料检查入口。
- 本片不新增固定底部提交栏，主按钮保留正常文档流，避免和现有手机底部导航、软键盘争夺空间。错误与状态文本可换行，长模型名称、哈希和请求 ID 不撑宽页面。

**UI-003 · 让勾选、保存与生成状态一致**

| 状态／动作 | 确认区表现 | 生成区与恢复 |
| --- | --- | --- |
| 新报价可用 | 默认未勾选；无旧报价的成功状态 | 禁用，提示先确认发送范围 |
| 勾选后等待当前报价的确认响应 | 立即显示勾选并锁住该框，状态文字「正在保存确认…」使用 `role=status` | 一直禁用，原因指向保存中的确认 |
| 当前报价确认成功且仍勾选 | 显示「已确认发送范围」和服务器确认时间 | 仅在有效期、预算等所有条件满足后可用 |
| 取消勾选 | 立即显示未勾选，不能同时展示无定语的「已确认」成功状态 | 立即禁用，提示需勾选；不显示「已撤销云端记录」等错误承诺 |
| 重新勾选 | 再进入「正在保存确认…」，不沿用页面旧成功状态放行 | 本次确认成功前仍禁用 |
| 确认失败 | 回退为未勾选，原位显示可朗读错误 | 禁用；可重新勾选，过期则先重新报价 |
| 报价更新/过期 | 新报价重置勾选与可用确认；过期使确认不可提交 | 当前报价与确认结果必须对应，旧异步响应不得使新报价出现成功状态 |
| 生成提交中 | 确认区保持当前事实，不启动新的确认或自动重报 | 按钮「正在创建任务…」且禁用，保留同次操作幂等行为 |
| 任务受理/已有任务 | 不把受理当成生成完成 | 受理结果与任务详情入口替代可提交操作；已有任务保持锁定并提供其入口 |

状态提示不依靠颜色单独传达。确认保存成功不强制把焦点移走，用户可继续 Tab 到生成按钮。报价倒计时不按秒触发整页朗读。受理可沿用 `role=status`，说明后台继续执行且服务需要保持运行；本片不自动跳转详情，也不改跨刷新恢复规则。

**UI-004 · 中屏标签与既有抽屉**

- `PageLayout` 的中屏多面板标签使用水平、自动激活模式。进入组时仅当前标签 `tabIndex=0`；其余为 `-1`，保留 `role=tablist/tab/tabpanel` 及双向 ID 关联。
- `ArrowRight` 激活并聚焦下一项，末项回首项；`ArrowLeft` 激活并聚焦上一项，首项回末项；`Home` 到首项，`End` 到末项。只拦截这些标签导航键，不阻止正常 Tab、Shift+Tab 或面板内部输入操作。
- 选择、焦点和内容在同一次操作中更新。Tab 离开当前标签进入活动面板的第一个可聚焦内容；若面板没有控件，则面板本身提供 `tabIndex=0` 的落点。不得用「每个标签都可 Tab 到」替代方向键实现。
- 鼠标点击仍切换对应内容；单面板直接呈现，不添空标签组。中屏侧栏显隐入口保持原行为。窄屏仍为单个模态抽屉，打开聚焦内部、Tab/Shift+Tab 留在抽屉、Esc/关闭按钮关闭并将焦点还给触发点；本片不改出处唤起面板的行为。

**UI-005 · 文字、触控与视口适配**

最终以浏览器的计算样式和实际点击矩形为准，不能只检查通用 CSS 声明；特别复核后置手机规则和更具体的阅读器选择器。

| 内容范围／现有组件线索 | 本片冻结的最小值与行为 |
| --- | --- |
| 新建/编辑及预算的表单标签、输入文字；确认区主要说明、发送列表、勾选标签；阅读器步骤操作正文与部件说明（`field__label/input`、`scope-list`、`checkbox-row label`、`step-detail li`、阅读器 `entity-list p`） | 字号 ≥14px；正文行高建议 ≥1.6，输入/列表可换行或按正常输入滚动处理 |
| 预算/字段辅助说明、缺项/禁用原因、错误提示、有效期、PDF 文字层、步骤/PDF 页码与必读状态（`field__hint/error/warning`、`confirm-actions__reason`、`original-panel__text`、`viewer-panel__notice`） | 字号 ≥12px；不能被卡片裁切或只以悬浮提示提供 |
| 主按钮、表单提交、向导导航、面板标签/触发器、抽屉关闭、步骤前后、原文前后页、查看出处按钮与文字替代操作 | 标签字号 ≥12px；375px 下其中 §3 所列触控操作的完整点击区域 ≥44px 高且 ≥44px 宽；长文案换行不减少点击高度 |
| 发送确认勾选 | 原生 checkbox 保留可识别形态，关联标签可点；整行提供至少 44px 高的操作区域，不要求 checkbox 图形本身画成 44px |

- 字号/尺寸实现需关注 `theme.css` 中 `.reader-page .entity-list button`、`.viewer-panel__toolbar button`、`.original-panel__nav button`、`.step-nav button`、`.step-detail li`、`.page__actions` 手机覆盖，以及页面入口主按钮的单独规则。使用范围明确的规则，避免小屏又退回 10–11px 或 28–32px。
- 375px 及桌面实际 200% 浏览器缩放时，必要内容可沿纵向滚动；确认卡片、表单、按钮组可收缩换行，无页面级横向溢出。可滚动的 PDF/3D 内容不作为缩小正文的理由。保留手机内容底部空间，使固定导航不盖住末尾输入、错误和操作。
- 所有受影响按钮、链接、输入、标签和原生折叠控件保持可见键盘焦点。选中状态保留文本/ARIA 表达，不仅更换底色；沿用减少动效规则。
- QA 使用真实有内容的阅读器检查正文与操作，而非空态代替。3D 旋转、拾取、遮挡、热点绑定及窄屏几何校准限制均无新增交互；既有 PDF 上传/准备和抽屉能力只做本片样式与焦点回归。
