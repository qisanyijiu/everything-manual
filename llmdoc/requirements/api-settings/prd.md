# 网页 API 配置 PRD

状态：DONE（AS-01 已实现，独立 QA 回合 1 全量 PASS，15 项 AC 通过；见 [验收报告](qa-report.md)） · request_revision：1 · prd_revision：1 · ui_revision：1 · 更新：2026-09-22

## 1. 目标与依据

依据 [用户请求](request.md)「提供api接口网页配置能力」，将现有 `/settings` 的只读供应商状态扩展为可保存的配置页。管理员可以填写应用实际使用的 Tripo 与说明书 AI 地址、模型和密钥；刷新后能找回已保存配置，并在重启服务后由真实服务端适配器使用。

当前 `AppState` 持有启动配置，任务执行器的供应商处理器也在启动时构造。因此本批采用明确的 **保存后重启服务生效**，不把仅写文件描述为立即生效。页面同时区分「当前运行配置」与「已保存、待重启配置」。本批成功标准是浏览器完成配置 → 服务端安全持久化 → 重启 → 本地供应商 fixture 实际收到新地址、模型与凭据对应的请求，而非只验证表单提示。

范围依据：[架构](../../architecture.md)、[接口合同](../../contracts.md)、[协作流程](../../collaboration.md)、[ADR-007/011/022/031 与后续脱敏记录](../../decisions.md)。最新用户请求替代旧文档「网页不输入密钥、设置只读」的限制；密钥仍仅由 Rust 发往供应商，读取 API 不返回密钥。现有 interaction-a 成果与 T22/T23 状态保持独立。

## 2. 范围与非目标

本批完整交付一个任务 AS-01：两张供应商配置卡、受认证与 CSRF 保护的读写接口、私有持久化、重启加载、状态反馈、配置切换与任务/报价的边界，以及对应自动化与浏览器验收。

仅支持现有协议：Tripo v3 与说明书 AI 的 Responses 适配器。自定义 Base URL 代表兼容该协议的服务地址，不代表支持 Chat Completions、Anthropic 或任意 OpenAPI 协议。不新增供应商发现、连接测试、真实付费探测、价格编辑、API key 申请、网页重启进程、TLS/证书/监听/目录配置或备份管理。保留现有输入限制、健康检查和部署边界展示。

### 3.1 字段与输入语义

| 字段 | 产品语义与校验 |
| --- | --- |
| Tripo Base URL | 使用既有 Tripo v3 API 基础地址，例如当前内置默认值；不是生成端点完整路径。 |
| 说明书 AI Base URL | 使用 Responses API 基础地址，例如当前内置默认值；不是 `/responses` 端点完整路径。 |
| Base URL 通用约束 | 必须是绝对地址且有主机；最长 2048 字符；允许 HTTPS；HTTP 仅允许明确 loopback 主机（`localhost`、`127.0.0.1`、`[::1]`）用于本机兼容服务；禁止 userinfo、查询串、fragment 和控制字符。去首尾空白，尾斜杠按适配器统一规范化。浏览器与服务器均校验，服务端为权威。保存不访问该地址。 |
| 模型 | 去首尾空白，最长 128 字符，不含控制字符；允许为空表示未配置，不猜测模型。任意填写只表示发送这个模型名，不能声称其受价格目录或适配器兼容性验证。 |
| 替换密钥 | password 输入；去首尾空白后必须非空、最多 4096 字符，拒绝不能安全作为 Authorization 值的控制字符/内部空白。不得在错误内容中包含输入值。可见性切换只作用于当次新输入，不读取已保存密钥。 |
| 保留密钥 | 保留当前已保存的密钥选择/来源；若尚无网页密钥覆盖，继续引用部署来源，不需要把环境变量密钥复制到网页持久文件。 |
| 清除密钥 | 保存明确的「无密钥」覆盖，屏蔽更低优先级密钥；要恢复环境/TOML 密钥须显式使用「恢复部署配置」。 |
| 恢复部署配置 | 重置该供应商的 Base URL、模型与密钥覆盖，不在浏览器内补造部署值；提交后服务端返回其已保存结果。另一家供应商不受影响。 |

### 3.2 并发与生效边界

1. 设置读取提供不含秘密的修订标识，保存携带该修订。其他标签页已保存时，过期提交返回冲突，不覆盖较新配置；页面保留当前输入，提供重新加载并说明会丢弃未保存编辑。
2. 保存的阻断检查与接受新任务/恢复任务操作必须有共同的序列化边界。并发结果只能是「任务先被接受，配置变更拒绝」或「配置先保存，任务拒绝」，不能二者同时成功且依赖不一致。
3. 非终态包括 queued、running、waitingProvider、retryWait、needsInput、submissionUnknown；还应检查被 cancelled/failed 任务遗留的未决 attempt 或仍需执行的供应商阶段。不能只检查展示层状态。
4. pending 状态下允许再次修订配置、清除密钥或恢复部署配置；不得由于再次保存短暂放开生成门禁。若结果完整回到当前运行配置，可清除 pending，但先前已失效的报价不恢复。密钥相等判断在服务端完成，不以密钥摘要作为公共字段。
5. 变更切换后的旧任务重试须返回明确的配置已改变原因，提示重新报价建立新任务；旧已受理幂等请求的重放仍只返回原业务结果，不新建单、不新增供应商动作。具体代次/指纹实现由 RD 决定，不得把密钥放入任务或报价快照。
6. 对这次网页保存作出的完整性保证不扩展为禁止部署者离线修改环境变量或配置文件；离线手改的运维风险需在实施记录说明，不能借此绕过网页路径的门禁。

## 5. 非功能与数据约束

- 新密钥仅存服务端私有配置，不入 SQLite 业务快照、报价、审计正文、备份或导出；受限文件采用先写临时文件后原子替换，失败保留旧版本。不要把秘密写入仓库、artifacts 或请求日志。测试使用明显假的专用密钥，证据也只记验证结果。
- GET 从未返回密钥明文，写入响应复用脱敏的读取结构；禁止 `Debug`/错误序列化把 DTO 中的新密钥打印出来。受限文件权限、无缓存响应和错误脱敏须有测试。
- 既有备份/导出的资产白名单不扩充私有配置文件。页面说明「备份与导出不包含 API 密钥；迁移服务后需重新配置」，不在本批制作新密钥备份工具。
- 配置保存有格式校验和本地构造校验，不作供应商连通性/余额/模型真实性保证；不跟随重定向传递 Authorization，不削弱既有下载域准入、费用、确认、幂等与发布不变量。
- OpenAPI 与前端类型按项目生成链同步；旧 `/settings/status` 消费者保持可用，可以新增字段但不能悄悄改变字段含义。原字段应仍代表当前运行配置；待重启对生成的额外阻断须可被确认页解释。
- QA 独立复验范围为本批全部 15 项 AC；证据隔离至 `artifacts/api-settings/`，不覆盖历史 web-mvp/interaction-a 证据。不要求为本批重新进行真实付费 T23 或完整发行平台认证。


- 两张供应商卡采用同一纵向顺序；桌面卡内字段可按两列排列，375px 全部单列。只设一个「保存配置」按钮整体保存两家，不设计每张卡单独落盘。保存区在文档流中，页面底部留出固定导航空间。
- 当前运行值是只读事实，不能随输入变化；编辑区从服务端**已保存值**初始化，标题为「下次启动配置」。表单未修改时显示「已保存」；编辑后显示「未保存修改」，不能把输入框内容标成已保存。
- 服务端返回 pending 时，页面常驻「已保存，重启服务后生效」，即使用户又修改了表单也保留此事实，同时另外显示「有未保存修改」。当运行与已保存值相同时标为「当前运行配置已生效」；其旁仍显示「连接未验证」，不使用“连接成功”绿灯。
- 正常时展示当前和已保存的地址/模型，以及密钥「已配置 / 未配置」和各自来源类别。密钥只存在布尔状态；即使当前和已保存都显示「已配置」，也不能据此推断密钥相同或展示指纹，是否待重启以服务端结果为准。
- 来源使用「网页配置」「部署配置」「默认值」「未配置」等中文类别；地址、模型、密钥来源不同则各字段注明，不能用单一标签误称整卡同源。下方说明「网页设置优先；恢复部署配置后使用部署侧设置」。不显示环境变量名或私有文件位置。
- 读取完成前显示带文字的骨架，表单不允许保存，也不填入猜测默认值。失败显示「无法读取 API 配置」及安全错误、requestId、「重新读取」；重试成功才初始化。后台读取不能自动覆盖 dirty 表单或清空新输入密钥。
- 缺模型/密钥按供应商列出缺项，允许按产品规则保存不完整配置；「未配置」与「未验证连接」分开。健康检查保留其本机含义，不能把就绪成功展示成第三方服务可用。

### 6.2 UI-AS-002：地址、模型与字段校验

关联 REQ-AS-002、008；AC-AS-003、004、005、014、015。

每个字段使用含供应商名称的唯一 label/ID，例如「Tripo Base URL」「说明书 AI 模型」。地址输入为 URL 语义，模型为文本；允许键盘粘贴。字段值来自读取结果，示例仅作 placeholder/说明，不作为尚未读到的实际配置。

| 字段 | 常驻说明与交互 |
| --- | --- |
| Tripo Base URL | 「填写兼容 Tripo v3 的基础地址，不是某个生成接口的完整地址。」 |
| 说明书 AI Base URL | 「填写兼容 Responses 的基础地址，不要填写完整的 /responses 接口地址。」不提供协议下拉框，避免暗示支持其它协议。 |
| 模型 | 「可留空；生成仍要求模型与服务端价格目录匹配。保存不会验证模型或余额。」不自动猜测或推荐模型名。 |
| URL 通用说明 | 「使用 HTTPS；本机 localhost、127.0.0.1 或 [::1] 可使用 HTTP。地址不能带账号密码、查询参数或片段。」 |

客户端按 §3.1 做格式检查，服务器仍是最终校验方。提交失败时在保存区显示错误摘要，逐项链接到字段，焦点移至第一个无效字段；字段通过 `aria-invalid` 与 `aria-describedby` 关联错误与说明。长值在只读摘要中换行，输入框按普通单行字段内部滚动，不撑宽页面。密钥错误只说「新密钥不能为空」「新密钥含不支持的空白或控制字符」等安全原因，绝不拼入用户输入。

### 6.3 UI-AS-003：密钥操作与恢复部署配置

关联 REQ-AS-003、004、007；AC-AS-006、007、013、014。

每张卡使用带 legend「密钥操作」的原生单选组，默认「保留现有」。当前密钥状态单独从读取结果显示，不用星号假值填入 password 输入框。

| 操作 | 字段呈现与提交前说明 |
| --- | --- |
| 保留现有 | 不显示已存密钥；说明「保留已保存的密钥选择与来源」。当前未配置时显示「当前没有密钥，保留不会补充密钥」。 |
| 替换 | 展开空的 password 输入，label 为「新的 Tripo 密钥」或「新的说明书 AI 密钥」。去首尾空白后非空才可提交；提示「仅保存这次输入的新密钥，已保存密钥不会回显」。可选的显示/隐藏按钮只作用于新输入，标签准确表达当前动作。 |
| 清除 | 不显示密钥输入，原位提示「保存后将不使用该供应商的密钥，也不会自动使用部署配置中的密钥；重启后该供应商不能生成」。选择本身不写服务端，仍需点击整体保存。 |

- 从替换切到保留/清除时清空新密钥输入，避免后来误提交；再次选择替换需重新输入。密钥输入使用合适的 password/autocomplete 设置，不用 value 属性、data 属性或隐藏字段保存副本；正常 React 表单内存和当次网络写入不作为额外缓存。
- 每卡独立提供「恢复部署配置」次级按钮。点击只将该卡标为「保存后恢复部署配置」，内联说明「将撤销本供应商的网页地址、模型和密钥覆盖；另一家不受影响；重启后使用部署配置」。不立即请求保存，也不在浏览器推测部署值。
- 恢复待保存时将该卡编辑字段和密钥操作替换为只读的恢复说明，显示「取消恢复」；新输入密钥立即清空。取消恢复回到该供应商**最近一次服务端已保存值**与保留模式，说明「已取消恢复；如需替换密钥，请重新输入」。另一家当前编辑不被重置。
- 整体保存按钮前列出本次清除或恢复的供应商名称及影响，无需再弹重复确认框。成功后两卡按服务端结果更新，所有新密钥输入清空、密钥操作回到保留，dirty 清除；读取不能获取任何旧/新密钥字符。写入失败不清空仍处于替换模式的输入，便于当前页修正/重试。
- 表单下方常驻「备份与导出不包含 API 密钥；迁移服务后需重新配置」。消息、URL、浏览器存储和证据中不出现密钥。离开且同意丢弃后，不恢复未保存密钥。

### 6.4 UI-AS-004：整体保存、双状态与重启指引

关联 REQ-AS-002、004、005、006、007、008；AC-AS-003、005、008、009、011、012、015。

| 状态 | 保存区／状态区表现 | 允许的下一步 |
| --- | --- | --- |
| 读取成功、没有编辑 | 「所有修改已保存」；是否已生效依服务端 pending | 可继续编辑；无变化不制造一次配置切换 |
| 存在编辑 | 「有未保存修改」；已有 pending 提示保持 | 「保存配置」；两家一起校验与提交 |
| 正在保存 | 按钮「正在保存…」且 `aria-busy=true`，阻止重复请求；提交期间冻结本表单编辑与清除/恢复按钮 | 等待本次结果；不通过保存发起连接探测或生成 |
| 保存成功且 pending | `role=status`：「已保存，重启服务后生效」；当前运行摘要保持原值，已保存值更新 | 按指引重启或继续修改；报价/确认/生成/恢复仍被暂停 |
| 保存无变化或恢复到当前运行配置 | 采用服务器返回状态，显示「配置未变化」或「当前运行配置已生效」 | 不声称旧报价重新有效；需重新报价的业务规则仍保留 |
| 重启后重新读取、pending=false | 「当前运行配置已生效」，两份值一致；仍「连接未验证」 | 按正常流程重新报价并显式确认 |

待重启区常驻文字：「新报价、确认与生成操作暂不可用；已有资料和任务记录仍可查看。」并给出产品确定的指引：「在运行服务的终端停止并使用原启动方式重新启动；使用进程管理器时重启对应服务，然后刷新此页。」可提供「刷新状态」只读按钮；dirty 时不得借此覆盖编辑，可只更新独立运行摘要/状态，若实现需要替换整表则先走 UI-AS-006 的丢弃提醒。页面不包含「测试连接」或「重启服务」按钮，也不展示含密钥的命令。

确认页若遭遇 pending、旧报价失效或配置代次变化，使用服务端原因明确提示「API 配置待重启生效，请前往设置」或「API 配置已改变，请重新报价并确认」，给对应导航；不得自动重报价、恢复旧任务或创建替代任务。这里仅要求必要原因呈现，不重新设计任务中心。

### 6.5 UI-AS-005：冲突、活动任务与失败恢复

关联 REQ-AS-001、002、006、007；AC-AS-001、002、004、005、010、011、012。

| 原因 | 可见结果与恢复 |
| --- | --- |
| 两标签页修订冲突 | 显示「配置已在其他页面更新，你的编辑尚未保存」，保留全部当前输入；冻结旧修订的保存入口。提供「重新加载已保存配置」，说明将丢弃本页编辑和新密钥；用户确认后读取新修订，成功才替换表单，失败则仍保留编辑与错误。不能自动把旧输入套入新修订再次提交。 |
| 非终态任务或遗留未决动作 | 显示「尚有任务或供应商操作未处理，暂不能更改 API 配置」，说明原配置仍在使用、此次未保存；提供「前往任务中心」。若服务端返回可用任务 ID 可链接对应任务，不凭空枚举原因或数量。不能提供“强制保存”或自动取消任务；离开设置仍执行 dirty 提醒。 |
| 持久化/网络失败 | 显示「未能保存配置」及服务端安全原因、requestId；不清空表单，不覆盖上次已知的已保存/运行状态，不展示成功。允许显式重试；网络结果不明时避免声称服务端一定未写入，提醒可重新读取核对，重试仍遵循修订校验。 |
| 401/403 | 沿用认证恢复；不展示或复用当前新密钥跨重新登录，401 离开受保护页时清空。403 在当前页提示权限/会话校验失败且本次未成功，不改显示值，不将错误细节写成密钥内容。 |
| 已保存模型未覆盖价格目录/供应商不可达 | 显示配置已保存的事实和「连接未验证」；保留模型/价格目录说明。不得把已有健康检查或保存成功当成可生成保证，也不主动探测第三方。 |

失败用 `role=alert` 或已有错误摘要，成功/保存进度使用 `role=status`，不让非字段错误强制把焦点跳到页首。无法识别的新错误保留安全文字与 requestId，不猜测已生效或自动重新发送配置。

### 6.6 UI-AS-006：未保存离开、手机与键盘

关联 REQ-AS-007、008；AC-AS-005、013、014。

- dirty 由相对最近服务端已保存值的编辑、密钥动作及恢复动作决定，不由是否聚焦或访问过字段决定。保存成功解除，保存失败不解除；仅 pending 而无本地编辑时离开不弹丢弃提醒。
- 站内导航使用单个确认对话框：「有未保存的 API 配置，离开将丢弃这些修改及新输入的密钥。」按钮为「继续编辑」（默认焦点）和「丢弃并离开」。Esc 等同继续编辑；取消后焦点回到发起导航的合理位置，保留全部输入；确认后清空临时输入再完成原目标导航。不为每个字段分别弹窗。保护范围仅本设置页，技术接入由 RD 决定，不要求迁移全站路由框架。
- 浏览器刷新/关闭使用 `beforeunload` 的原生提醒；不承诺自定义文案。重启后手动刷新若表单有 dirty 同样先提醒；未保存密钥不通过浏览器持久化来“恢复”。
- 375px 不并排放两家卡片；标签在字段上方，单选选项、状态摘要和恢复说明可折行，保存区无横向溢出。正文/输入/字段标签至少 14px，辅助说明至少 12px；保存、恢复/取消恢复、重试、显示/隐藏、对话框按钮等点击区域至少 44×44 CSS px，单选关联标签至少 44px 高。
- 采用原生 label、fieldset/legend、radio 与 password；Tab 按视觉顺序通过字段和操作，单选组保留原生方向键行为。新密钥展开时不抢焦点；键盘继续 Tab 即进入新输入。所有字段、按钮、链接和对话框焦点清晰，状态不只用颜色表达。
- 固定手机导航不能遮住当前字段、错误或保存按钮。长 URL/模型/请求 ID 在只读区换行；恢复说明和弹窗可以在屏内滚动。无新增装饰动效。3D、PDF 上传/准备及原有离开保护不受本页新增交互改动。
