# API 密钥加密存储 PRD

状态：UI_READY（rev2 提交边界已映射既有设计；尚未验收） · request_revision：1 · prd_revision：2 · ui_revision：2 · 更新：2026-10-01

## 1. 目标与依据

[用户请求](request.md)：「修改下，各种API key都要加密存储，避免泄漏」。当前网页覆盖文件和 `api_key_file` 的 0600 权限只能限制读取，不能保护被复制出去的文件。本批把应用支持的全部 API key 持久入口改为认证加密，并提供旧文件迁移路径。

本批覆盖 Tripo、说明书 AI 及其共用配置读取/持久化代码，不把「全部」解释为扫描、改写用户电脑上其他应用的凭据。沿用 [api-settings 最终 PRD](../api-settings/prd.md)、[实施记录](../api-settings/implementation.md) 的配置优先级、保留/替换/清除/恢复、CAS、重启生效和任务代次语义。管理员登录密码仍使用原有 Argon2 方案；不改变账号或会话。

成功标准：应用自行保存的 API key 和部署密钥文件均为可认证的密文；复制仓库/data-dir/备份不能同时取得解密主密钥；正确主密钥可跨进程重启读取并用于本机 fixture；篡改、错误/缺失主密钥不能使应用回退读取明文。环境变量来自外部注入，只在内存中使用，不宣称其已被本应用落盘加密。

## 2. 交付范围

一张完整任务 **ES-01**：共享加解密与主密钥来源、网页覆盖写入/启动迁移、两家 `api_key_file` 读取和显式加密命令、错误与最少界面说明、部署文档及独立验收。

不新增轮换平台、网页主密钥输入、密钥导出/查看、连接测试、新供应商、真实收费调用或自动清理用户外部文件。仅为支持上述路径添加必要 CLI；不在参数或示例命令中放明文 API key/主密钥。现有服务由协调者按完成情况更新预览；测试使用隔离数据目录。

### 3.1 主密钥与认证格式

- 依据 RD 已确认的本地依赖，使用 `ring::aead::AES_256_GCM`、32 字节随机主密钥、每次新加密操作独立的 12 字节 OS 随机 nonce；认证标签与密文一并保存。显式环境注入接受严格 32 字节的十六进制表示。文件格式版本与业务 revision 分离，具体序列化结构由 RD 在实施记录冻结，不由前端选择。
- 默认 macOS 系统凭据库通过 `security-framework` 原生库/API 使用，不将主密钥作为子进程参数、shell 命令或 stdout 传递。初始化使用 create-only 行为，并发冲突只读取已存在的胜者，不用 upsert 覆盖；不启用云同步。可保存非秘密 key ID/用途标识；这些标识不等于主密钥。不同 data-dir 的命名/共享策略须由 RD 记录，不能因复制目录而悄悄创建错误新密钥。
- 显式环境注入优先于默认系统凭据库；注入格式错误即报错，不静默尝试另一来源。非 macOS 无注入时不能创建持久秘密。主密钥不支持从项目 `.env`、TOML、API 或 data-dir 同目录明文文件自动发现；文档不得建议把它提交进仓库。
- 对已有密文读取可以请求读取既有系统凭据，不能在「找不到」时重新生成。首次创建新密文或迁移有效旧明文时才可初始化主密钥。`check` 保持只读，不生成主密钥或重写文件；发现旧网页明文时提示通过正常受锁启动完成迁移。
- 不要求开发者证明无法从被控制的进程内存取回秘密；运行时发请求仍需短暂明文。持久化对象和临时缓冲的 Debug/错误输出必须脱敏，并减少无必要的明文复制；清除内存的实现边界如实记录。

### 3.2 迁移与文件规则

| 入口 | 新行为 | 失败与恢复 |
| --- | --- | --- |
| 新网页保存 | 内存校验后直接序列化为密文，受限临时文件同步后原子替换；不得创建明文临时文件或明文备份。 | 原子提交前的加密/落盘失败保持旧文件、revision、pending；安全错误与 requestId，不把输入插入错误。提交后的目录同步错误保留已提交状态，见 §3.4。 |
| 旧网页明文覆盖 | 仅识别既有合法格式；在排他锁内先完整校验，成功生成并验证密文后原子替换。保持原 revision 和字段语义。成功后应用管理的该文件路径及遗留本次临时文件不含明文。 | 提交前失败保留原文件以便恢复，拒绝启动相关服务，不继续以旧明文运行；不得把任意损坏密文误认作 legacy。提交后不恢复旧明文，见 §3.4。 |
| 外部 `api_key_file` 明文 | 常规读取拒绝；显式加密命令输出新密文文件，提示更新 `api_key_file` 引用，并由操作者在验证成功后处理原明文及其旧副本。 | 不自动删除、覆盖或加密共享外部源文件；源文件哈希不变。失败目标不可被误认作有效密文。 |
| 已加密 `api_key_file` | 两家共用安全 reader；同一主密钥与格式规则；权限、符号链接、文件大小/类型校验至少保留并补齐至与网页私有文件相同的安全边界。 | 认证失败/未知版本/不安全文件类型均拒绝，不回退为文本密钥。 |
| 环境变量 API key | 只传入内存 `SecretString` 和现有供应商请求路径。 | 缺失仍按原未配置语义；应用不替用户改 shell 配置或外部秘密管理系统。 |

Unix 新密文及临时文件权限为 0600；敏感目录遵循原 data-dir 限制。持久化写入沿用原子替换与失败清理；不得用「先写明文再加密」实现。原明文的历史磁盘块、系统快照和用户既有备份不能通过普通文件替换保证物理抹除，文档如实说明，不声称已全盘清除。

### 3.3 供应商反射与部署 URL

本批检查发现：供应商可能在错误回复或成功诊断 JSON 中复述请求携带的 key；即使配置已加密，直接保存回复仍会另造明文副本。因此对本批运行中已知的两家 API key，在进入错误摘要、日志、任务事实、原始诊断 blob 等持久路径前，处理直接文本及 JSON 解码后的反射。优先保留不敏感诊断；不能可靠处理的敏感原始回复可不保存，不能以“逐字节诊断合同”保留秘密。业务错误/拒绝/未知状态仍按既有语义分类，不伪造成功。

部署 Base URL 同样不得携带 `username:password@host`；配置加载失败只报字段与固定原因，不插入原始值。此要求覆盖 TOML/环境的共用 provider resolver，补齐网页入口已有的限制。只处理已知秘密与直接/JSON 转义形式，不承诺识别任意编码、供应商侧留存或清理历史数据；不新增全体用户资产加密。

### 3.4 原子提交与断电持久性边界

此处限定「失败时旧文件不变」的可实现边界，不降低认证加密、禁止明文回退或原子整份发布要求：

1. 提交前先打开并同步父目录，确认目录句柄和当前同步能力可用；随后仅写密文临时文件并完成文件同步。上述步骤或发布操作失败时，不发布新文件，旧文件字节与业务修订保持不变，清理本次临时密文，并返回明确未保存。目录预检查不能保证之后的同步永不失败。
2. 原子 `rename` 成功是覆盖文件不可回退的提交点；显式加密命令创建新目标时采用等价的、不覆盖已有目标的原子发布点。提交成功意味着当前文件命名空间已包含完整密文，应用必须将已保存内存值、revision 与 pending 更新到该已提交事实。
3. 提交后应再同步父目录以增强断电持久性；若此时同步失败，保留已提交的磁盘文件与内存状态，记录不含秘密的安全告警，明确目录持久性未得到确认。不能返回「本次未保存」、保留旧 revision 假装未提交，或通过恢复旧明文文件/备份进行回滚；迁移同样不得退回明文。
4. 该告警不代表密文认证失败，也不要求新增网页操作；网页沿用已保存及待重启的真实状态，CLI/日志如实记录提交后同步告警。运行供应商配置仍遵循原重启生效合同。对进程已提交后立刻断电、文件系统/硬件损坏的持久性不作超出操作系统保证的承诺。
5. QA 分别注入提交前错误和提交后目录同步错误：前者验证旧字节不变/未保存，后者验证完整密文已发布、内存/修订一致、安全告警且无明文回滚。不得用提交后告警豁免可在提交前检测到的权限、文件写入/同步或发布失败。

## 5. 最少界面与异常合同

本节仅产品语义；UI 在 §6 补充现有页面中的具体位置与文案，不另建密钥管理页面。

| 状态 | 用户能看到的事实与下一步 |
| --- | --- |
| 网页密钥已保存 | 密钥在服务端加密保存、保存后重启生效；不显示密文/nonce/key ID/主密钥/密钥尾缀。 |
| 环境来源 | 由部署环境注入，仅在运行内存中使用；不承诺外部 shell/.env/秘密系统的存储方式。 |
| 保存时主密钥不可用 | 本次未保存，编辑仍在；提示检查系统凭据库访问或服务端主密钥注入，并提供 requestId。 |
| 启动/CLI 认证失败 | 加密配置不可读取，请恢复原主密钥或重新配置；不得建议通过删除密文/回退明文绕过。 |
| 外部明文未迁移 | 停止常规读取并说明使用本地加密命令生成新文件、更新引用、验证后由操作者处理原明文。 |

### UI-ES-002：加密保存失败与原位恢复

| 可确定的服务端错误 | 页面事实与下一步 |
| --- | --- |
| 主密钥缺失、系统凭据库锁定或拒绝访问 | 「密钥未能加密保存，本次配置未保存。请检查服务端的系统凭据库访问权限或主密钥环境注入；当前编辑仍保留，可在恢复后重试保存。」 |

以上「本次未保存」仅用于服务器明确返回未提交的加密/落盘错误；网络结果不明继续沿用原有「重新读取核对」文案。恢复环境后由用户再次点击原「保存配置」。原重新读取入口仍按 dirty 规则提示丢弃，取消时保留新输入；非字段错误不抢焦点。错误只携带安全原因与 requestId，不复述密钥、主密钥、原 URL 或解密内容。

## 8. 决策与边界

- **静态加密，planned，2026-10-01**：保护文件副本被读取的场景；操作系统账号、主密钥或运行进程已被控制时不保证保密。用户请求不应被解释为绝对防泄漏承诺。
- **系统凭据默认 + 显式注入，planned**：macOS 提供可用的默认路径，非 macOS 沿用外部部署密钥管理；避免把解密钥匙与密文放在同一目录或仓库。具体成熟库由 RD 可行性结果冻结。
- **外部文件不自动改写，planned**：共享部署文件可能被其他程序使用，显式输出新密文可验证、可恢复。原文件残留须明确告知，不冒称已清除所有历史明文。
- **迁移不改业务代次，planned**：加密格式变更不改变供应商、模型、密钥值或用户同意，应保留既有任务/报价语义。
- **提交点与持久性，planned，rev2**：普通文件系统的原子替换不提供跨后续目录同步的回滚事务；rename 成功后准确承认完整密文已提交，保持磁盘/内存/修订一致。提交后同步故障仅作安全持久性告警，不能恢复明文；提交前可检测错误仍保证不发布、旧字节不变。见 §3.4，影响 REQ-ES-006、AC-ES-006/008/010；无新增界面或授权要求。
- **无新增用户选择阻塞**：默认路径已确定；真实系统凭据访问若出现工具/系统权限失败，记录准确阻塞，先完成不依赖该环境的实现与验证，不能以 mock 覆盖真实验收。
