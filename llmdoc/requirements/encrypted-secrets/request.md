# API 密钥加密存储

日期：2026-10-01。用户请求：「修改下，各种API key都要加密存储，避免泄漏」。

背景：网页 API 配置已完成。当前 `provider-overrides.json` 的替换密钥和部署 `api_key_file` 为 0600 明文；Git 已忽略运行目录、覆盖文件及临时文件。用户现授权实现真正的静态加密，而非仅说明或修改权限。

目标：梳理并统一项目支持的所有 API key 存储入口（Tripo、说明书 AI，以及共用供应商密钥读取路径），使用成熟的认证加密；主密钥与密文分离，不能随仓库、备份或导出泄漏；现有明文配置安全迁移，损坏/错误密钥时拒绝读取，不静默降级为明文。运行时请求上游仍需短暂明文，环境变量仅作为外部注入，不主动持久化。

兼容约束：保留网页保留/替换/清除/恢复和重启生效语义、修订 CAS、任务/报价代次门禁及登录账号；不取消任务，不使用真实收费供应商，不提交或推送。保留所有已有工作树改动。采用 PM → UI → 单一 RD → 独立 QA；本批工作目录 `encrypted-secrets`，证据只写 `artifacts/encrypted-secrets/`。

实现需如实说明威胁边界：加密保护静态文件泄漏，不承诺在操作系统账号、主密钥或运行进程已被控制时仍能保密。原有 API 配置验收保持历史结论，新批独立验证加密、迁移、泄漏边界与必要回归。
