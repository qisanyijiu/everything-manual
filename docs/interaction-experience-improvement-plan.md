# 万物说明书：交互体验改进方案

日期：2026-09-19  
状态（2026-09-20）：**切片 A 已实现并通过独立验收，B/C/D 待实施**。实施范围见 [interaction-a](../llmdoc/requirements/interaction-a/prd.md)，实际结果见 [QA 报告](../llmdoc/requirements/interaction-a/qa-report.md)。下文仍为完整改进方案，不代表各项均已实现或验收，也不改变 T22/T23 的状态。

## 1. 结论与目标

建议下一轮从“页面已经能用”推进到“用户始终知道下一步、能从中断处继续、能核对每次操作的结果”。重点投入流程连续性和阅读效率，延续现有暖白、墨绿、橙色视觉，不再另起一轮纯配色改造。

优先落地六件事：

1. 「创建并继续」直接进入上传说明书，向导展示真实完成状态。
2. 从服务端找回资料准备记录，换标签页后仍能继续。
3. 预算、发送范围、确认与生成按钮在同一条阅读路径上。
4. 发布待办可以直接定位到对应条目，处理完继续下一项。
5. 点击原文出处时自动展开正确的 PDF 面板或抽屉。
6. 补齐标签页键盘操作，并提高正文可读性和移动端点击面积。

随后再完善物品状态摘要、搜索、保存反馈、任务恢复和导出入口。

## 3. 目标操作流程

### 3.1 第一次建立说明书

```text
新建物品 → 上传说明书 → 上传并标注照片 → 准备资料
         → 预算与发送范围确认 → 提交生成 → 后台任务
         → 复核待办 → 发布 → 打开阅读器
```

每一页回答三个问题：现在做到哪一步、还缺什么、主要按钮会发生什么。上传和准备仍不触发收费；生成与发布仍分别由用户显式发起。

### 3.2 再次回来继续工作

```text
资料库 → 当前状态及推荐动作 → 恢复对应步骤/任务/草稿
```

由服务端事实决定恢复位置，不用上一次访问的 URL 或浏览器缓存猜测业务状态。有历史发布版的物品，即使新任务失败，也应继续提供旧版本阅读入口。

### 3.3 日常查阅

```text
找到物品 → 直接打开最新发布版 → 选择部件或步骤
        → 查看对应原文 → 返回原来的阅读位置
```

历史版本、模型信息与导出放在次级入口；需要核对原文时，不应再次手动寻找隐藏的面板。

## 5. 具体改进方案

### UX-01：一个物品，一个主要的下一步

**建议交互**

资料库行保留名称、型号和更新时间，增加有业务含义的进度标签。主操作随状态变化，其余操作进入明确的次级区域。不要为每件物品请求一整套文档、照片、任务和草稿详情来拼状态。

| 当前事实 | 状态文案 | 主操作 | 补充入口 |
| --- | --- | --- | --- |
| 尚未绑定说明书 | 待上传说明书 | 上传说明书 | 编辑物品 |
| 缺必要视图 | 待补齐照片 | 补齐照片 | 查看资料 |
| 有未完成准备记录 | 资料准备中断 | 继续准备 | 查看准备详情 |
| 输入满足报价前置条件 | 可开始生成 | 核对预算 | 查看资料 |
| 任务排队/运行 | 生成中 | 查看进度 | 阅读已有版本（如有） |
| 任务有明确待处理项 | 需要你处理 | 处理问题 | 阅读已有版本（如有） |
| 已有待复核草稿 | 待复核 | 继续复核 | 阅读已有版本（如有） |
| 已发布且无待办 | 可阅读 | 打开说明书 | 历史版本、导出 |

建议的优先顺序为：需要用户处理的任务 → 进行中的任务 → 待复核草稿 → 最新发布版 → 资料缺项。归档状态单独显示，不用它代替处理进度；多个任务/草稿并存时由服务端返回确定的目标 ID，用户仍能查看全部。

**实现边界**：建议增加物品摘要读取能力，返回推荐动作类型、目标实体 ID、状态依据和最新发布版 ID。具体端点/字段名在实施时更新合同；不要把本表当作已经存在的 DTO。API 返回枚举与 ID，前端通过白名单路由映射，不直接执行任意 URL。

**验收**：不同状态 fixture 的主操作与目标一致；摘要加载失败显示「状态暂不可用」，保留查看物品详情；已有发布版不因新任务失败而不可读；加载 N 件物品不产生 N 组详情请求。

### UX-02：让向导真正连续

**建议交互**

- 「创建并继续」成功后进入该物品的说明书上传步骤；概览保留为导航入口。
- 步骤显示「已完成 / 当前 / 待补充 / 需重新检查」，而不只显示步骤名称。完成条件来自当前资料与准备记录，不能以“访问过页面”判完成。
- 为长页面提供一致的底部操作区域：返回上一步、当前缺项、下一步。手机上避开底部导航与键盘，不能盖住错误或输入框。
- 上传保持选文件入口，补充拖放、文件卡片、单文件进度和局部重试；文件类型和上限取服务端配置，不再另写一份可能过期的固定值。
- 视图槽位增加简短方向示意，说明前/后/左/右以物品自身为准；照片上传成功与视图绑定成功分别反馈。
- 替换已绑定 PDF/视图时说明后续需要重新核对哪些步骤。不能改变运行中任务的冻结输入，也不能悄悄复用不兼容的准备结果。

**验收**：创建成功自动进入第 2 步；返回已完成步骤不会重复上传；缺项提示可定位对应输入；单个文件失败只重试该文件；已有资料和新选未上传文件的状态有明确区别。上传增强可以在创建跳转与步骤状态之后单独交付。

### UX-03：恢复资料准备，不依赖记住标签页

**建议交互**

进入物品或准备页面时查询服务端已有准备记录。显示「已完成 x/y 页」「上次处理时间」「继续准备」；封存成功则显示「资料已准备好」。sessionStorage 仅用于快速找到候选记录，丢失时仍可查询恢复。

准备期间把「取消」改成更准确的「停止准备」，并常驻说明“已完成页会保留，之后可继续”；如实现不保留运行中的浏览器任务，就不要称为可以瞬时恢复的“暂停”。

**服务端前置**

增加按物品/说明书发现 preparation 的读取能力，至少能辨认来源文档、来源哈希、准备格式/版本兼容性、页数、已完成页和是否 ready。只有与当前输入兼容的记录才可用于报价。多条记录并存时，按明确规则推荐可复用记录，并允许查看记录列表；不把“最后创建”简单等同于“可复用”。

**验收**：新标签页重新打开能发现已有记录；已完成页不重复处理，缺页继续补齐；原件更换后旧记录不能误用于新报价；记录缺失/损坏明确报错而非假显示 0%；关闭浏览器中断准备，已经提交的后端生成任务仍可继续，两者文案清楚区分。

### UX-04：把生成确认放在一条阅读路径里

**建议交互**

用页面内的连续区域代替报价、确认各藏在不同侧栏：

```text
① 本次资料：物品 / PDF 页数与范围 / 视图缩略图
② 费用与授权：Tripo credits ｜说明书 AI USD
③ 将发送给谁：照片 / 页图与文字 / 型号信息
④ 显式勾选发送确认
⑤ 开始生成（旁边显示两类预算上限与报价有效状态）
```

预算和确认是主要内容，技术明细可折叠。所有尺寸都能沿页面向下读完，不要求先发现某个抽屉。确认请求尚未成功时显示「正在保存确认」，生成按钮保持不可用。

报价过期显示「报价已过期，重新获取后再确认」；修改资料后说明报价失效原因。开始生成成功进入任务详情，显示“任务已创建，关闭页面不影响后台执行（服务需保持运行）”。

**保留边界**：credits 与 USD 不相加；报价不等于收费；发送范围默认不勾选；新报价需要重新确认；不自动重报、不自动重放付费请求；结果未知进入核对路径。后台仍以服务端报价、幂等和费用规则为准。

**验收**：375/768/1024/1440px 都能直接找到费用、发送范围和确认控件；禁用原因紧邻操作；过期、确认失败、预算不足分别有可行动提示；重复点击和断线重试不形成第二个业务操作。

### UX-05：把复核工作区变成可处理的待办

**建议交互**

顶部显示「还需处理 n 项」，按文字事实、模型核对、热点/视角分组，并提供「只看未完成」。点击待办应完成四件事：选中对应实体、展开对应面板、滚动到条目、将焦点移到正确控件。处理成功后提供「下一项」。

热点操作采用显式模式：选择部件 → 开始绑定 → 在模型上点选 → 显示绑定结果。始终显示当前正在绑定的部件、退出绑定入口和保存状态，拖动旋转不得误建点。旧模型热点以「模型已更换，需要重新绑定」解释 stale。

发布区域显示清单结果与主操作；不满足条件时给「还需处理 n 项」并跳到首项。服务端返回的发布问题同样映射到相应实体，未知问题保留完整文字与诊断信息，不能静默丢弃。

**保留边界**：文字事实确认与几何校准独立；模型加载与用户核对两个声明独立；不能批量“确认全部”代替逐项核对，不能自动确认失效热点；窄屏仍不开放几何校准，保留原有能力边界和明确说明。

**验收**：每个有实体 ID 的待办可定位到正确对象；完成项后计数更新且不跳回页面顶部；422 问题可处理；412 时保留编辑内容并提示刷新核对；满足条件后仍需用户显式发布。

### UX-06：点击出处，就看到原文

**建议交互**

- 将 PageLayout 面板的打开状态、活动标签和定位目标提升为可控制的页面状态，供出处跳转和待办定位共用。
- 点击「第 n 页」时同时设置文档、页码、目标面板与焦点。中屏切到原文所在标签；手机从部件抽屉切到原文抽屉，保持同一时刻只开一个抽屉。
- 原文显示“来自部件 / 来自步骤”的简短上下文，提供返回原部件/步骤的位置。
- 增加页码输入、适应宽度、原文放大查看；范围外页码给字段错误。保留前后翻页和文字层作为基础路径。
- 原文加载失败提供局部重试；3D 加载失败不阻塞原文。没有来源框坐标时只跳页，不伪造高亮区域；多份原件存在时不能固定把所有出处指向第一份文档。
- 阅读模式优先展示当前步骤和原文，完整部件列表作为可切换面板；校准模式优先展示部件与绑定工具。布局按实际内容区域是否放得下调整，不能只考虑浏览器宽度而忽略新增全局导航。

**验收**：在原文隐藏时点出处，一次操作即看到目标页；关闭抽屉焦点回到合理的来源控件；页码、页图、文字层一致；换尺寸不丢选中部件/步骤/页码；模型转动、热点选择和原文阅读互不阻塞。

### UX-07：统一保存、离开与异常恢复的反馈

**建议交互**

输入编辑明确展示「未保存 / 保存中 / 已保存 / 保存失败」，上传使用真实字节进度，PDF 使用真实页数，供应商生成显示真实阶段与等待时间，不展示无法证实的百分比或完成时间。

只对存在未保存编辑、进行中的上传/准备提供离开保护；普通查阅与已经进入后端的任务不反复打断。准备页已有 beforeunload，应补齐站内路由切换的对应行为，并在退出前明确哪些内容已经保存。恢复草稿可以提示用户选择，不自动覆盖服务端版本；不把密钥、会话信息、PDF 或照片内容写进浏览器持久存储。

任务详情按「发生了什么 → 已保存什么 → 现在能做什么」组织异常。保留按阶段的重试/对账入口，区分“重试读取状态”和“重新提交生成”，不要合并成一个含义不清的重试按钮。取消任务继续说明不能保证撤销供应商收费。

**需要单独验证**：确认页目前在组件 ref 中持有建单幂等键，刷新后的恢复体验应专项检查；不能据此直接断言后端会重复收费。建议恢复时先读取服务端已有报价/任务状态，只在用户明确操作后继续，同一次未知提交不得生成新的业务操作键。若现有 API 无法查到结果，再补读取合同。

**验收**：模拟断网、401、412、上传中离开、准备中站内跳转、建单响应丢失；错误明确区分“失败”和“结果待核对”；恢复后保留用户输入，且不自动生成新收费请求。

### UX-08：完成键盘、触控和字号的可用性闭环

**项目设计目标（拟定）**

- 步骤正文与常用表单文字以 14–16px 为目标；辅助信息通常不小于 12px。9–10px 仅保留给非必要装饰标记，不能用于关键操作或必读说明。
- 手机主要点击目标以至少 44×44 CSS px 为目标，可以通过扩大点击区实现，不要求图标本身变大。
- 标签页支持左右方向键、Home/End、合理的焦点与选中联动；Tab 能离开标签组进入当前面板。该行为与现有 roving tabIndex 一起实现，避免只移除 tabIndex 约束掩盖缺失逻辑。
- 错误、选中、已完成不只用颜色表达；焦点框在浅底、深色导航和模型区域都可见。
- 保留 Esc 关闭、抽屉焦点陷阱及关闭后焦点恢复。滚动、放大和虚拟键盘出现后，底栏不能遮挡输入、错误或下一步按钮。
- 保持减少动效模式，不添加与业务无关的入场动画或强制相机运动。

**验收**：只用键盘完成登录、创建表单导航、面板切换、出处跳转和关闭抽屉；375px 及 200% 浏览器缩放下能读完关键说明并操作主按钮；触控实测相邻操作不会频繁误点。这些是项目验收目标，不在未测量时宣称已符合某项外部标准。

### UX-09：让资料库适合持续使用

**建议交互**

非空资料库缩短首页介绍区，让搜索、待处理物品和主要操作更靠近首屏；首次空库保留完整引导。计数继续如实标注已加载数量，服务端没有总数时不展示“全部物品共 n 件”。

将“显示已归档”改成语义明确的「使用中 / 已归档」切换，因为现有 API 是切换查询范围，不是把归档结果叠加到当前列表。状态筛选、排序和名称/型号搜索进入 URL，返回列表时恢复筛选与滚动位置。

当前搜索仅作用于已加载页，先保留明确说明和无结果提示。后续如增加服务端名称/型号搜索，应与分页、归档条件共同绑定游标，不能用加载全部数据的方式假装服务端检索；本轮不扩展为全文索引或语义搜索。

**验收**：分页外的名称/型号由服务端搜索找到；换筛选后重置无效游标；前进/后退恢复范围和位置；无结果时给「清除筛选」；失败时保留上一份数据并标注可能过期。

### UX-10：补齐版本、导出与配置的产品入口

**建议交互**

- 有发布版时，资料库主操作可直接打开最新发布版；完整版本列表作为次级入口。列表显示发布时间和可读版本标签，原始 UUID 保留在详情中。
- 使用现有 `GET /api/v1/releases/{releaseId}/export` 增加「下载说明书资料包」入口，说明包含 PDF、GLB、manifest 与校验信息。它不是可双击打开的网站，也不是整库备份。
- 下载过程中说明由浏览器处理；只有能检测到的失败才展示具体错误，不把“已发起下载”伪称为“已保存到磁盘”。大包避免为了状态提示而先完整读进浏览器内存。
- 在开始创建流程和报价前，以只读配置状态提前告知缺少生成能力，提供设置页入口，但允许用户继续管理已有资料。设置页给准确的配置帮助，不新增前端密钥输入，也不自动尝试收费 API。
- 区分首次未登录和真正的会话过期，首次访问显示普通登录提示；重新登录后返回原步骤。当前 [RequireSession](../apps/web/src/features/shell/RequireSession.tsx)在探测到 401 时统一设置 expired，可据此细化。

**验收**：入口下载的版本与阅读器一致；没有发布版时显示真实空态与准备/复核入口；未配置 Provider 的已有版本仍可阅读；首次登录不错误提示“已过期”。

## 7. 验证计划与完成标准

### 7.1 场景验收

| 场景 | 核心断言 |
| --- | --- |
| 新用户从空库开始 | 建物品后直达上传；每一步完成状态来自数据；缺项可定位 |
| 先创建资料但未配 Provider | 提前告知缺配置；允许上传和查阅；没有外部收费请求 |
| 上传中断、准备中断 | 已完成部分保留，明确剩余工作；换标签页能够发现准备记录 |
| 生成中刷新或关闭页面 | 已建任务可找回；不会因页面重开而再次付费提交 |
| 报价失效、确认失败 | 不能开始生成；原因和恢复动作处于可见主流程 |
| 复核多条内容 | 待办定位、连续处理、保存失败与冲突均可理解 |
| 模型更换 | 旧热点不能假显示为有效，旧发布版仍可读 |
| 阅读器中点击出处 | 宽屏、中屏、手机均打开正确文档/页码并给出返回位置 |
| 3D/WebGL 不可用 | 文字与 PDF 可继续查阅，局部恢复不影响其他区域 |
| 键盘、缩放与手机触控 | 标签组、抽屉、表单、主操作均可达，不被底栏遮挡 |
| 发布和导出 | 显式发布，生成同一不可变版本；导出的资产属于该版本 |
| 搜索和列表返回 | 查询覆盖约定范围，游标条件一致，返回位置可恢复 |

### 7.2 工程与人工检查

- 单元测试优先覆盖推荐动作映射、面板导航状态、准备记录兼容性、报价过期与恢复分支，不为纯装饰结构编写镜像测试。
- 浏览器回归覆盖真实路由、操作结果、抽屉/标签键盘行为、关键错误路径；375/768/1024/1440px 作为建议检查宽度，同时检查长中文名称和长错误提示。
- 对 API 变更运行后端对应集成测试与合同漂移检查；前端运行构建、Lint、现有单元测试和本切片 E2E。每次报告实际执行范围，不沿用旧 QA PASS 当作新布局的证据。
- 默认使用本地 fixture。真实供应商质量、费用与延迟仍属于授权后的 T23，不纳入这份文档的已验证结论。

### 7.3 可用性目标（先测基线，再比较）

建议邀请 3–5 位未参与开发的人执行“新建、恢复、复核、阅读”任务，人工记录，不引入外部分析 SDK，也不采集说明书内容。

| 指标 | 建议目标 | 计量方法 |
| --- | --- | --- |
| 下一步可发现性 | 至少 4/5 用户无需提示，10 秒内指出主要操作 | 物品典型状态截图/实际页面任务 |
| 出处可达性 | 1 次出处点击即使正确原文进入视野 | 包含原文最初隐藏的中屏/手机场景；网络加载时间单列 |
| 复核待办定位 | 1 次待办点击定位到对应实体与控件 | 文字未确认、缺热点、失效热点三类 fixture |
| 恢复成功率 | 所有规定的中断 fixture 均可恢复，兼容的已完成页不重复处理 | 服务端记录、请求数量与界面状态共同核对 |
| 重复提交保护 | 同一操作的重复点击/响应丢失恢复不新增付费操作 | 幂等键、任务数和 fixture 请求数 |

这些目标尚未测量。人数不足时记录原始成功人数与具体阻碍，不把小样本百分比当作总体结论。

## 8. 不扩展的边界

本方案不包含多用户协作、分享平台、自动事实确认、自动热点生成、机械分件/爆炸动画、全文/语义检索、后台 PDF 原生渲染或网页填写 API 密钥。首页的示意插画不代表这些能力已经存在。

不以改善体验为由放宽后端发布不变量、费用确认、未知提交对账、资产归属、If-Match 或不可变版本约束。改进应让这些规则更容易被用户理解和执行。
