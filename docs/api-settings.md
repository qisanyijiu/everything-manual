# 在网页中配置 API

状态：已实现，2026-09-22 通过独立 QA 全部 15 项验收。需求与生效约束见 [API 配置 PRD](../llmdoc/requirements/api-settings/prd.md)。

加密升级：已实现，2026-10-02 通过独立 QA 全部 12 项验收，并更新本地预览。见 [加密存储验收报告](../llmdoc/requirements/encrypted-secrets/qa-report.md) 与 [交付记录](../llmdoc/requirements/encrypted-secrets/state.yaml)。

## 配置入口

登录万物说明书后，进入侧栏或手机底栏的「设置」。API 配置包括两个独立服务：

| 服务 | 用途 | 接口要求 |
| --- | --- | --- |
| Tripo | 根据物品照片生成 3D 模型 | 兼容现有 Tripo v3 协议 |
| 说明书 AI | 根据准备好的说明书提取知识草稿 | 兼容现有 Responses 协议，模型需支持所用图像与结构化输出能力 |

自定义地址不会自动转换协议。仅支持 Chat Completions 的服务不能直接当作 Responses 服务使用。

## 填写和保存

1. 核对每张卡的「当前运行配置」，在「下次启动配置」填写 Base URL 和模型名。
2. Base URL 填接口基础地址，不要追加某个操作的端点。例如说明书 AI 不追加 `/responses`。使用 HTTPS；本机 `localhost`、`127.0.0.1` 或 `[::1]` 允许 HTTP。地址不能包含账号密码、查询参数或片段。
3. 首次添加密钥或更换密钥时，选择「替换」并填写新密钥。只改地址或模型时可以选择「保留现有」。已保存的密钥不会回显，输入框为空不代表密钥已丢失。
4. 点击「保存配置」。两家配置一起校验和保存；错误会指出需要修改的字段。
5. 看到「已保存，重启服务后生效」后，在运行服务的终端停止服务，并使用原启动方式重新启动；使用进程管理器时重启对应服务。然后刷新设置页，核对当前运行值与已保存值一致。

保存不会验证连接、余额或模型支持情况，也不会上传资料或发起收费生成。待重启期间暂停新报价、确认与生成操作，已有资料和任务记录仍可查看。

## 读取说明书 AI 可用模型

在说明书 AI 卡片点击「读取可用模型」，服务端会使用**当前已生效**的地址和密钥，向基础地址的 `/models` 发起一次 GET 请求。页面未保存的输入和待重启配置都不参与；若刚修改地址或密钥，请先保存并重启。没有生效密钥时无法读取。

列表读取后不会自动修改模型。选择一项仅填入模型字段，仍须点击「保存配置」并重启服务。可以继续手动填写模型名称；列表存在不保证该模型支持 Responses、图像或结构化输出，也不表示服务端价格目录已覆盖该模型。

受保护接口是 `POST /api/v1/settings/providers/manual-ai/models`，需要登录、CSRF 与同源检查，不接受地址或密钥参数。返回仅含合法模型 ID 的 `{ "data": ["模型名称"] }`，不包含上游元数据。读取不跟随重定向、不自动重试，整体超时 10 秒，响应上限 256 KiB、1000 项；错误不会回显上游正文或密钥。它不上传说明书、不发起生成，也不保存配置。打开设置、刷新设置和保存配置均不会自动触发模型读取。

## 保留、清除与恢复

| 操作 | 保存后的含义 |
| --- | --- |
| 保留现有 | 保留最近已保存的密钥选择和来源；没有网页密钥覆盖时，继续引用部署配置。 |
| 替换 | 使用这次输入的新密钥；替换模式不接受空值。保存成功后输入框清空。 |
| 清除 | 明确不使用该供应商的密钥，也不回退到环境变量或配置文件里的密钥。重启后该供应商不可用于生成。 |
| 恢复部署配置 | 撤销这一家供应商的所有网页覆盖，包括地址、模型与密钥；另一家不受影响。仍须保存并重启。 |

供应商的网页覆盖优先于环境变量、配置文件与默认值。修改和恢复操作在点击整体保存前都只是本页编辑。

## 遇到问题

- **提示有未处理任务或供应商操作**：到任务中心查看并处理，不能通过更换账号或地址继续旧任务。取消任务后若远端结果仍不明，仍需先按已有对账流程处理；保存不会自动取消任务。
- **配置已在其它页面更新**：当前编辑尚未保存。先确认是否丢弃本页编辑，再重新加载最新配置；不要反复提交旧版本。
- **保存失败或连接中断**：页面保留当前编辑供修正。网络结果不明时，重新读取核对服务端状态，再决定是否重试。
- **已配置但仍不能报价/生成**：密钥和模型齐全不等于连接已验证；生成还要求服务端价格目录覆盖当前模型，以及资料、预算、发送确认等条件满足。价格目录和部署参数仍由服务端管理，参见 [config.example.toml](../config.example.toml)。
- **配置改变后旧报价或旧失败任务不能重试**：重新获取报价并确认后建立新任务，避免复用旧账号或旧地址的授权。

未保存修改离开页面时会提醒丢弃；新输入的密钥不保存在浏览器本地存储中。备份和导出不包含 API 密钥，迁移服务后需重新配置。

## 密钥加密存储

网页新增或替换的 Tripo / 说明书 AI 密钥使用 **AES-256-GCM 认证加密**，密文保存在服务端 `data-dir/provider-overrides.json`。每次加密使用新的随机 nonce，文件格式和用途参与认证；篡改、错误主密钥或未知格式会被拒绝。文件与临时文件仍为 Unix 0600，写入直接产生密文，不生成明文备份。

主密钥与密文分离：

- **macOS 默认**：使用当前服务运行用户的默认系统钥匙串，条目 service 为 `org.everything-manual.secrets.v1`、account 为 `master`，不启用云同步。同一系统用户下的多个数据目录共享该主密钥。首次确实需要保存密钥时创建主密钥；读取已有密文只查找原主密钥，不会自动创建替代品。换系统用户或机器后，单独复制数据目录不能取得原主密钥。
- **Linux 等其他系统**：通过部署侧秘密管理机制注入 `EM_SECRETS_MASTER_KEY`，值为 32 字节随机主密钥的 64 位十六进制编码。macOS 无人值守也可使用此方式。该显式值优先于钥匙串，格式错误或解密失败不会回退到其他来源。应用不生成同目录主密钥文件，也不自动读取项目 `.env` 来寻找它。
- 将主密钥独立保管，重启与迁移时持续提供同一个值。不要放进仓库、命令行参数、示例文件、普通日志或与密文一起备份。丢失原主密钥后，原密文无法解密，需要恢复原主密钥；加密本身没有可绕过的恢复密码。

通过 `api_key_env` 注入的供应商密钥只在内存中使用，本应用不将它复制到网页覆盖文件。其外部存储由部署方负责；页面显示「部署配置」不能说明它来自环境还是密文文件。登录密码继续使用已有 Argon2 哈希，和可解密的 API key 是不同用途。

## 旧密钥迁移

**网页旧文件**：新版 `serve` 在取得数据目录锁后、启动 HTTP 与任务执行器前，校验并原子替换合法旧明文覆盖。仅改变存储格式，保留 revision、密钥值和任务授权代次。迁移失败时保留原文件并拒绝继续启动；`check` 只检查，不执行迁移或创建主密钥。

**部署 `api_key_file`**：新版正常读取仅接受密文，旧明文需先显式加密。以下命令不包含密钥值，输入文件须为受限普通文件，输出必须不存在：

```sh
./everything-manual encrypt-api-key --provider tripo --input /secure/tripo.key --output /secure/tripo.api-key.enc
./everything-manual encrypt-api-key --provider manual-ai --input /secure/manual-ai.key --output /secure/manual-ai.api-key.enc
```

命令须使用与服务相同的系统用户及默认钥匙串，或注入与服务相同的主密钥值。完成加密后，把 TOML 中对应供应商的 `api_key_file` 改为新密文路径；相对路径仍相对服务启动目录解析。两家密文绑定各自用途，不能交换文件使用。保持原有 `api_key_env` / `api_key_file` 二选一规则，然后正常重启服务并核对配置。

命令不会覆盖或删除原明文，也不自动修改部署文件。验证新配置后，由操作者处理原明文及其旧副本，尤其是被其他程序共用的文件。替换文件不能保证抹除 SSD 历史块、系统快照或既有备份。

若系统钥匙串锁定/拒绝访问，或主密钥注入不可用，保存会失败并保留本页输入。恢复原钥匙串凭据访问后可重试保存；环境注入在进程启动时读取，须由部署系统修正并重启服务后再保存。网络结果不明时先重新读取核对。已有密文无法认证时，应恢复原主密钥并检查文件完整性，不要删除密文或改回明文来绕过错误。

文件写入、同步和发布前检查失败时，旧配置保持原样。完整密文原子发布后，如果最终目录同步失败，配置仍按已提交处理并记录安全告警；此时磁盘断电持久性无法确认，应检查服务端存储。应用不会把已提交误报为「未保存」，也不会恢复明文副本。

## Git 与泄漏边界

仓库忽略 `var/`、`data/` 等运行目录，以及任意目录下的 `provider-overrides.json`、`*.api-key.enc` 和对应临时文件；部署密文仍应放在仓库之外。不要将 API key 或主密钥复制进代码、示例配置或项目文档。`.gitignore` 不会移除已跟踪文件或历史提交，也不能阻止 `git add -f`；若真实密钥曾被提交，应先撤销并更换，再处理 Git 历史。

读取接口不回传已保存的密钥；供应商回复中直接或 JSON 转义回显的已知密钥，会在错误、任务事实和诊断持久化前作安全处理。无法安全解析的供应商响应正文也会被丢弃，只保留安全诊断和原有失败/结果未知状态，不据此自动重复收费请求。备份与导出不包含私有密钥配置或主密钥，新实现不负责清理旧版本已存在的日志、备份或其他历史副本。

静态加密保护被复制出去的文件。请求供应商时服务仍需在内存中解密；系统账号、主密钥或运行进程已被控制时，不能靠静态加密保证保密。
